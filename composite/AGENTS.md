# COMPOSITE 프로젝트 상시 지침

이 지침은 이 저장소의 플랫폼, 테스트, 문서 및 소개 자료 작업에 적용한다.

1. 사용자가 요청한 변경을 구현한 뒤 관련 파일을 Git에 커밋하고 원격 저장소에 push한다. 작업 완료 전에 원격 반영을 확인한다. 사용자가 명시적으로 커밋·push·배포를 금지한 경우 그 요청을 우선한다. 사용자의 무관한 변경을 덮어쓰거나 임의로 함께 커밋하지 않는다.
2. 원본 도면 기준은 **DWG**이다. 설계·업무 프로세스·자료를 DWG 기반으로 유지한다. 현재 샘플 시제품의 기능과 아직 구현하지 않은 DWG 읽기/쓰기·CAD 연동을 명확하게 구분한다. SVG 내보내기를 DWG 내보내기로 표현하지 않는다.
3. **업무 프로세스** 탭을 배치 스튜디오와 별도로 유지한다. 단계, 담당, 입력·산출물, 재검사 및 승인 흐름이 실제 구현 범위와 일치하도록 갱신한다.
4. **Git 소스와 배포된 플랫폼 로직은 같은 버전이어야 한다.** 테스트한 소스를 커밋·push한 뒤 그 정확한 커밋으로 배포한다. `node scripts/check.mjs`를 통과하고, push 후 `node scripts/verify-git-sync.mjs`로 clean tree 및 원격 main과 HEAD의 일치를 확인한다. Sites 저장 버전의 source.commit_sha가 같은 HEAD인지 확인하고 해당 버전의 배포 성공을 확인한다. Git에 없는 코드만 서버에 직접 적용하지 않는다. 브라우저의 임시 설비 배치 데이터는 소스 Git과 별개이며 자동 영구 저장을 구현한 것처럼 말하지 않는다.
5. **구현 후 반드시 테스트한다.** 관련 자동 테스트와 실제 UI 주요 동작을 확인한다. 실패하면 원인을 수정하고 실패한 검사 및 영향받은 회귀 테스트를 다시 실행한다. 테스트·배포가 실패했거나 검증하지 못한 상태를 완료라고 보고하지 않는다. 완료 보고에는 실제 테스트 결과와 남은 제한을 알린다.
6. **플랫폼 소개 PPTX를 Git에서 관리한다.** `docs/COMPOSITE_Platform_Introduction.pptx`와 재생성 소스·필요 자산을 유지한다. 표와 부제목을 적절히 사용하고 업무 프로세스는 편집 가능한 플로우차트로 표현한다. 기능이나 흐름이 달라지면 소개 자료도 맞춰 갱신한다. 슬라이드를 렌더링해 글자·표·선의 겹침과 잘림을 검토한다.
7. **최종 답변의 맨 마지막에는 플랫폼 링크와 이번 개발 내용이 반영된 GitHub 링크를 반환한다.** 실제 반영을 확인한 저장소·폴더 또는 커밋 URL을 사용한다. 반영 실패 시 완료된 링크로 표현하지 않고 상태를 명시한다.
8. **DWG 업로드 → 객체 DB 추출 → DB 편집을 핵심 기능으로 유지한다.** 별도의 DWG 데이터베이스 탭을 제공하고 도면 원본, 추출 객체, 편집 결과·이력을 서버에 저장한다. 원본 추출값과 수정값을 구분하고, 지원하지 않는 객체·파싱 실패·저장 실패를 성공으로 처리하지 않는다. DB 편집과 원본 DWG 재기록은 별도 기능이며 실제 지원 범위를 표시한다.
9. **삼성전자향 FAB 설계 플랫폼으로 개발한다.** Bay를 생산설비와 인프라 배치의 기본 검토 단위로 사용한다. 실제 프로젝트의 Bay 경계·설계 조건을 편집 가능하게 하고, 공개되지 않은 삼성전자 사내 표준이나 수치를 추정하여 기본 기준으로 단정하지 않는다.
10. **배치와 컴포짓은 하나의 설계 스튜디오에서 검토한다.** 업로드한 실제 CAD 형상을 표시하고 생산설비 BOX, 전기분전반·VMB·배관·덕트·전기 모듈랙·인동선 레이어를 분류·검수한다. 도면 안에서 객체 위치를 이동하고 DB에 반영하며 미지원 형상·단위·검수 미완료 상태를 표시한다.

## 저장소와 배포

- 플랫폼 실행 소스: `dist/`
- 공유 업무 모델: `dist/workflow.mjs`
- 검사: `node scripts/check.mjs`
- 테스트 결과 기록: `docs/VALIDATION.md`
- 저장소 원격: `origin` (프로젝트에 연결된 Sites Git 저장소)
- 배포 프로젝트: `.openai/hosting.json`의 기존 `project_id` 재사용
- 새 등록·새 사이트 생성 없이 기존 비공개 사이트에 업데이트
- Git 토큰과 서버 비밀값은 코드·설정·PPT·커밋·로그에 저장하지 않는다.

이 지침은 작업 시 지켜야 할 절차이며, 무인 예약 작업이나 자동 CI가 이미 설치되었다는 의미는 아니다.

## 공개 기업 사례를 반영할 때

- 삼성전자·SK하이닉스 공식 사례, 공동저자 연구, 관계사 특허 및 향후 계획을 구분한다. 관계사의 방법을 해당 제조사의 실제 사내 표준으로 표현하지 않는다.
- 근거 URL과 확인 범위를 `docs/RESEARCH.md`, 화면의 `dist/research.mjs`, 소개 PPT에 함께 갱신한다.
- 치수·공종 높이·이격·UT 용량 기본값은 자체 예시임을 유지한다. 사내 수치나 DWG 자동 컴포짓 알고리즘을 확인하지 않은 상태에서 추정값을 회사 기준으로 넣지 않는다.
- GitHub와 Sites Git이 별도 이력을 가질 경우 커밋 ID가 같다고 주장하지 않는다. 승인된 GitHub 대상에 같은 파일을 반영하고, 배포 소스 커밋 및 파일 해시로 대응 관계를 기록한다. 다른 프로젝트 파일은 보존한다.
