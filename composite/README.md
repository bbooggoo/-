# COMPOSITE · 삼성전자향 FAB 설계

실제 DWG를 올려 객체 DB를 만들고 생산설비 BOX와 인프라를 하나의 설계 스튜디오에서 검토하는 플랫폼입니다. 별도의 DWG 데이터베이스·업무 프로세스 탭을 제공합니다.

## 구현 기능

- DWG 원본·레이어·객체 추출 및 로그인 사용자별 서버 저장. 원시 Handle 대조로 변환 누락을 검사합니다.
- 실제 CAD 평면 표시, 블록 내부 레이어 표시/숨기기, 공종 분류, 드래그·좌표 이동·위치 고정.
- 생산설비 BOX, 전기분전반, VMB, 배관, 덕트, 전기 모듈랙, 인동선 구분. 복수 선을 하나의 BOX로 묶고 해제할 수 있습니다.
- Bay 경계 및 인프라 구역 방향·폭 설정. BOX 이격·인동선·Bay 위반 검사와 고정 객체를 보존하는 배치 제안.
- BOX 자동 정리: 작은 선 틈 연결, 다른 속성란의 건설코드 통합, 유일한 외부 코드 문자를 BOX 안으로 이동. 수정 후보 확인 후 적용합니다.
- 객체 JSON·메모·공통 건설코드 편집. 원본 추출값·원본 DWG 보존, 변경 전후·사유·개정 이력 및 재검수.
- 동일 스튜디오 안의 접을 수 있는 2.5D·UT **별도 예시**: 높이·체적·이격·Hold·UT 용량·POC·두 배치 대안·JSON 보고서. 실제 업로드 DWG와 자동 연결되지 않습니다.

## BOX 자동 정리 규칙

도면 단위 확인 → 프로젝트 허용오차·검색거리·속성란 별칭 입력 → 선 연결과 코드 후보 분석 → 변경 Handle·이동량·보류 사유 확인 → 안전한 수정 적용 → DB 저장·원본 대조·재검수.

열린 폴리라인은 끝점 틈이 허용오차 이내이고 폐합 후 단순 다각형인 경우만 닫습니다. LINE은 같은 레이어의 끝점 관계가 유일한 폐회로만 연결합니다. 분기·중복·교차·고정 형상·곡선 폐합은 자동 보정에서 제외합니다. 건설코드는 `건설코드, CONSTRUCTION_CODE, BUILD_CODE, EQUIPMENT_CODE, 설비코드` 등의 별칭을 읽어 `_constructionCode`에 보관합니다. 원본 속성란은 지우지 않습니다.

문자와 BOX 귀속이 유일한 경우만 연결합니다. 직사각 BOX 안에 들어갈 크기의 회전 없는 외부 문자를 이동하며, 문자 폭은 근사값입니다. 누락된 값은 만들지 않습니다. 공유 건설코드를 허용하며, 프로젝트 설정으로 중복을 오류 처리할 수 있습니다. 미해결 정리 항목은 저장 후에도 검수 완료를 막습니다. 수동 보완 후 다시 분석해야 합니다.

## 저장과 실행

Node.js 22 이상과 pnpm 11을 사용합니다.

```text
pnpm install --frozen-lockfile
node scripts/check.mjs
node scripts/dev.mjs
```

로컬 주소는 `http://127.0.0.1:4317`입니다. 로컬 어댑터만 테스트 사용자 ID를 주입합니다. 배포 Worker는 Sites 인증 헤더를 요구하며 사용자별 도면 접근을 분리합니다. 사용자 도면은 Git에 포함하지 않습니다.

| 경로 | 역할 |
|---|---|
| `dist/` 최상위 | 실행 프런트엔드 소스 |
| `server/worker.mjs` | 원본 파일·객체 DB·편집·검수 API |
| `db/schema.ts`, `drizzle/` | D1 스키마와 생성된 마이그레이션 |
| `dist/client`, `dist/server`, `dist/.openai` | 빌드 산출물, Git 제외 |
| `.local-data/` | 로컬 테스트 D1/R2 데이터, Git 제외 |
| `docs/COMPOSITE_Platform_Introduction.pptx` | 소개 PPTX |
| `docs/presentation/` | PPT 재생성 소스·검사 도구 |

브라우저는 DWG를 전용 Worker/WASM에서 읽습니다. 서버 R2에는 원본 DWG, D1에는 원본 추출 JSON·현재값·이력을 저장합니다. 위치 변경은 원본 좌표와 구별되는 `_placement`로 남깁니다. 여러 객체 저장은 최대 40개 단위로 진행하며 각 묶음은 독립적인 개정입니다. 중간 실패 시 이미 저장한 묶음은 유지되고 남은 변경을 다시 저장할 수 있습니다. 전체 대량 저장을 하나의 트랜잭션이라고 표현하지 않습니다.

## 지원 한계

- 파일 20 MB, 추출 객체 10,000개, 객체 DB 16 MB. 브라우저 메모리와 도면 복잡도에 따라 더 작은 파일로 나눠야 합니다.
- DWG 엔진의 일부 객체, XREF·동적 블록·프록시·HATCH·3D 실체·비평면 OCS 등의 완전한 표시를 보장하지 않습니다. 변환 경고·누락·표시 미지원은 검수에서 차단합니다.
- 2D 평면과 축 정렬 경계 기반 검사입니다. 곡선은 분할 근사, 글꼴·문자 폭·서식은 근사 표시입니다. 실제 배관/덕트 높이 간섭, 관경·곡률·유지보수 공간 검증 및 3D 라우팅은 별도 개발 범위입니다.
- 자동 배치 최대 200개 객체, BOX 선 정리 최대 1,200개 원시 형상. 계산 한도를 넘으면 범위를 나눠야 합니다. 최적해를 보장하지 않습니다.
- **DB 수정값의 원본 DWG 재기록은 미지원**입니다. 원본 DWG 다운로드와 편집 DB는 구분됩니다.
- 테스트는 공개 DWG 및 자체 오류 사례로 수행했습니다. 실제 삼성전자 생산 도면 검증은 아직 하지 않았습니다.
- 공개 기업 연구는 참고 근거이며 사내 표준을 재현했다는 의미가 아닙니다. [RESEARCH.md](docs/RESEARCH.md), [THIRD_PARTY.md](docs/THIRD_PARTY.md)에서 출처·엔진 GPL 고지·대응 소스를 확인할 수 있습니다.

## Git·배포 일치

코드·테스트·문서·PPT를 검사하고 커밋한 뒤 origin/main에 push합니다. `node scripts/verify-git-sync.mjs`로 clean tree 및 원격 일치를 확인하고 같은 커밋을 기존 비공개 Sites에 배포합니다. `.openai/hosting.json`의 D1 `DB`, R2 `BUCKET` 바인딩과 생성된 마이그레이션을 함께 배포합니다. 런타임 DDL과 비밀값은 소스에 넣지 않습니다.

GitHub의 `bbooggoo/-/composite/`에는 다른 프로젝트 파일을 보존하면서 동일 소스를 반영합니다. Sites Git과 GitHub는 이력이 다르므로 GitHub의 대응 기록에 Sites 소스 커밋과 파일 해시를 남깁니다. 도면 DB와 소스 Git은 별개의 저장소입니다. 무인 CI가 설치되었다는 의미는 아닙니다.
