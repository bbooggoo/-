## 실제 브라우저 동작

로컬 플랫폼의 공개 실제 DWG 샘플 버튼으로 **파일 선택과 같은 `File → upload() → WASM Worker → R2 원본 → D1 객체` 경로**를 실행했다. 6개 실제 형상, 레이어 2개, AutoCAD 2018·mm 추출을 확인했다. 기본 단위 확인·레이어 분류·BOX 수·Bay 검수는 미완료로 시작한다.

- 공종 분류와 BOX 후보·단위·Bay 기준 설정 후 서버 R2 개정 저장.
- 실제 원 형상을 마우스로 끌어 이동. X -24.259622390675077, Y +11.833962141792767 이동을 서버 R3로 저장.
- 현재 개정 검수 기록 후 새로고침. 위치·건설코드·Bay·검수 상태가 유지됨을 확인.
- DB 상세에서 원본 추출 JSON에 이동값/건설코드가 섞이지 않은 것을 확인. 변경 사유와 전후 이력이 존재.
- 자체 예시에서 0.01 m 틈의 폴리라인을 0.02 m 허용오차로 폐합하고 BUILD_CODE 값을 공통 FAB-101 코드로 정리. 수정 2건과 나머지 BOX의 코드 누락 7건을 구분.
- 분석 후 객체를 편집하면 이전 수정 후보의 적용 버튼이 비활성화되고 다시 분석하라는 문구가 나타남.
- 예시 Bay 자동 배치 3개 이동 후 검사 0건. Bay 기존 경계 편집과 저장본 복원 확인.
- 통합 스튜디오 안의 별도 2.5D 예시 대안 기능 유지: 이동 최소 4개/4.70499 m, 연결거리 우선 5개/55.46898 m, 두 대안 필수 위반 0건.
- 1280px 데스크톱과 390×844 모바일에서 3개 탭·도면·업무 흐름을 확인. 모바일 페이지 전체의 가로 넘침 없음(문서 폭 375px/뷰포트 390px). 테이블은 내부 스크롤.
- 마지막 브라우저 콘솔 error/warn 0건. 테스트 뷰포트 설정은 복원함.

도구의 파일 선택기 이벤트는 3초 제한으로 완료되지 않아 OS 파일 선택 동작 자체를 자동 검증하지 못했다. 이를 DWG 파싱 성공으로 대체해 표현하지 않는다. 동일 업로드 함수의 실제 DWG 추출·서버 저장 경로는 공개 샘플 버튼으로 검증했다. 실제 사용자의 생산 도면은 제공되지 않았으며 삼성전자 실도면 검증을 주장하지 않는다.

## 배포 전 확인

원본 DWG 재기록, 임의 3D 실체/프록시/XREF 전체 표시, 실제 인프라 높이 간섭·라우팅 및 현장 승인은 미지원이다. 코드 누락을 만들어 채우지 않으며, 정리 미해결 항목은 재분석 전까지 검수 완료를 막는다. 수정 DB 저장과 원본 DWG는 분리한다.

테스트한 소스를 커밋·push하고 원격 main과 clean HEAD를 검사한 뒤 해당 커밋으로 기존 비공개 Sites를 배포한다. GitHub의 `composite/SOURCE_SYNC.json`은 배포 소스 커밋과 파일 해시 대응을 기록한다. 서로 다른 두 저장소의 커밋 ID가 같다고 주장하지 않는다. 실제 저장 버전·배포 성공·원격 대응 확인은 최종 완료 보고 시 확인한다.
