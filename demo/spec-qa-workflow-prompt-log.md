# 제원 질의 데스크 — 지금까지 작업한 내용을 프롬프트 형태로 정리

아래는 이번 세션에서 순서대로 요청했던 내용을 하나의 작업 지시서(프롬프트) 형태로 재구성한 것입니다.
다른 세션에서 이 아티팩트를 다시 만들거나, 같은 요구사항을 재현하고 싶을 때 그대로 붙여넣어 쓸 수 있습니다.

대상 아티팩트: `제원 질의 데스크` (https://claude.ai/code/artifact/fb3bc871-7c09-439d-88cd-0a6d971ef58c)

---

## 1단계 — 불필요한 질의 정리 (값 없음 / 설비모듈)

> 값이 쓰여있지 않거나, 설비모듈에 대해서는 질의를 하지 않아. 불필요한 질의니깐.. 그런 질의 케이스는 모두 삭제하도록 해.

- `qa_threads` 중 `status: RESOLVED`이면서 `toBeValue`가 비어 있는(null) 항목을 찾는다.
- 이 중 연결된 `corrections` 문서에 실제로 반영된 값(`newValue`)이 있는 건은 **삭제하지 말고** `toBeValue`를 그 값으로 채워 복구한다(질의 자체는 유효했으므로).
- `fieldLabel === "설비모듈"`인 질의는 업무상 불필요한 질의로 보고, 해당 `qa_threads` 문서와 연결된 `corrections` 문서를 모두 삭제한다. 단, 이미 `spec_sheets`에 반영되어 있는 값 자체는 되돌리지 않는다(감사 이력만 정리, 실데이터는 유지).
- 처리 후 통계로 검증: 빈 TO-BE를 가진 RESOLVED 질의가 더 이상 없는지, 설비모듈 질의가 더 이상 없는지, 이미 반영된 제원표 값이 그대로인지 확인한다.

## 2단계 — 업무 프로세스 간소화 (플로우차트 재설계)

> 빨간색 테두리 친데는 없어도 될것 같아. 그리고 너가 생각했을때 가장 효율적인 업무 프로세스를 생각하고 그걸 플로우 차트에 넣어줘. 가장 효율적인 방식이라는건 설계사와 기술팀 담당자가 최소한으로 질의응답 사항들을 확인하도록 하는거야.

- 기존 흐름은 "① AUTO 질의 → ② MANUAL 질의 → ④ 답변완료(TECH_ANSWERED) → 설계사 검토 → ⑤ 답변승인(ANSWER_APPROVED) → 기술팀 확인 → ⑥/⑦ → 설계사 최종확인 → ⑧ 종결" 으로, 설계사·기술팀이 왕복 확인해야 하는 단계가 많았다.
- 이를 "기술팀 1회 판단(AS-IS 유지 확인 또는 값 제안) → 설계사 1회 최종확인"만 남도록 압축한다:
  - AUTO 질의: 기술팀 확인(즉시 종결) 또는 특이사항 시 기술팀이 곧장 값을 제안 → 설계사 최종확인.
  - MANUAL 질의: 설계사가 등록하면 기술팀이 한 화면에서 "AS-IS 값 유지 확인" 또는 "값 제안" 중 하나로 즉시 결정 → 설계사 최종확인.
  - 설계사가 반려하면 다시 기술팀의 판단 단계로 돌아간다(단일 재질의 루프).
- 상태값을 `OPEN → VALUE_PROPOSED → RESOLVED/REJECTED` 로 단순화하고, 답변완료/답변승인 단계로 이어지던 기존 버튼·화면(서술형 답변 등록, AS-IS 값 승인, 답변 검토, 값 확인/제원 변경 등)을 새 흐름에 맞는 버튼(AS-IS 값 유지 확인 / 값 제안 / 최종 확인 / 재질의)으로 교체한다.
- 플로우차트(SVG)와 "단계별 설명" 목록, 상태 칩 문구를 전부 새 흐름에 맞게 다시 그리고 다시 쓴다.
- **이미 만들어져 예전 흐름(답변완료/답변승인) 단계에 있던 기존 질의들도 모두 새 상태로 마이그레이션한다** — AS-IS 값이 이미 확인된 건은 곧장 `VALUE_PROPOSED`로, 아직 기술팀 판단이 끝나지 않은 건은 `OPEN`으로 되돌려 새 화면에서 다시 판단하게 한다.

## 3단계 — 플로우차트 겹침 제거 + 지침화

> 플로우차트가 문구나 선이 겹쳐있지않게 해주고 해당 사항들을 지침에 추가해줘.

- SVG 좌표를 좌표 계산으로 직접 검증해 다음 두 가지 겹침 버그를 고친다:
  1. 화살표가 다른 도형(박스) 내부를 가로지르는 경우 — 특히 되돌이(재질의) 화살표가 같은 행에 나란히 있는 다른 박스를 관통하지 않도록, 그 박스의 아래/위로 우회시킨다.
  2. 화살표 라벨(문구 배경 박스)이 인접 도형과 겹치는 경우 — 라벨의 bounding box와 인접 rect/diamond의 bounding box를 좌표로 비교해 충분한 여백(최소 15~20px)을 두도록 좌표를 다시 배치한다.
- 좌표를 코드로 뽑아 겹침 여부를 스크립트로 재검증한다(라벨 vs 도형, 화살표 선분 vs 도형 교차 체크).
- 이 규칙을 **코드 주석(지침)으로 `buildFlowSvg` 함수 바로 위에 남겨** 이후 관리자가 문구나 좌표를 고칠 때도 같은 문제가 재발하지 않도록 한다(라벨 배치 규칙, 화살표 우회 규칙, 진입점 분산 규칙, 텍스트 길이-도형 크기 규칙, 캔버스 밖으로 잘리지 않게 하는 규칙 등 5가지).

## 4단계 — 필요 없어진 항목(레거시 코드) 정리 + 설계사용 필터 추가

> 기존 제원 질의했던것 중에서, 업무흐름도가 변경되면서 필요없어진 항목들은 모두 삭제해줘. 설계사랑 기술팀이 진짜 확인 필요한 한것들만 남겨줘. 그리고 설계사도 자기가 단계별로 봐야할거를 분류해서 필터로 만들어줘.

- 2단계 마이그레이션으로 `TECH_ANSWERED`/`ANSWER_APPROVED` 상태의 질의가 실제로 0건임을 다시 확인한 뒤, 이제 코드에서만 남아있던 해당 상태 관련 요소를 전부 제거한다:
  - 상태 라벨/칩(`QA_STATUS_LABEL`, `QA_STATUS_CHIP`, `OPEN_STATUSES`)에서 두 상태 제거.
  - 기술팀 필터 목록에서 더 이상 절대 나오지 않는 항목(예: 답변승인 단계 전용 "제원DB수정 필요") 삭제, 남은 항목은 "판단 필요"/"AUTO 확인 필요" 두 가지로 재정리.
  - 그 상태를 처리하던 화면 함수(답변승인 화면), 상태 전이 함수(답변 검토/값 확인 즉시종결), 관련 버튼 핸들러를 전부 삭제.
  - 업무 가이드 탭 통계에서도 다시는 늘어나지 않을 옛 지표(서술형 답변 등록 횟수, 답변승인 횟수, 답변 반려 재질의 횟수)를 빼고, 새 흐름에서 계속 의미 있는 지표만 남긴다. 대신 "AS-IS 유지로 처리했는지" 여부를 새 필드(`initiatedAs`)로 남겨 최종 승인 시 "AS-IS 유지 승인" vs "값 변경 승인"을 계속 구분 집계할 수 있게 한다.
- 설계사 쪽에도 기술팀과 대칭되는 필터를 새로 만든다: 자신이 등록한 MANUAL 질의를 "최종확인 필요한 항목(값 제안됨 — 실제 조치 필요)"과 "기술팀 판단 대기중인 항목(아직 할 일 없음, 참고용)"으로 분류하는 `설계사 확인 유형` 드롭다운을 질의응답 탭 필터에 추가하고, 질의 카드에도 해당 칩을 표시한다.

### 참고 — 이번 세션에서 실제로 겪은 제약사항 (재현 시 유의)

- 이 아티팩트는 `db` 캐패빌리티(Claude Artifact의 실시간 공유 저장소)를 쓰므로, DB 쓰기(`write_db`)가 세션 정책에 따라 일시적으로 막힐 수 있다 — 이 경우 코드(아티팩트) 변경부터 먼저 반영하고, 쓰기 권한이 돌아오면 기존 데이터 마이그레이션을 마저 진행하는 순서로 작업했다.
- 대량 마이그레이션은 `write_db`의 `batch`(최대 50건)로 나눠 처리했고, 메시지 이력 전체를 매번 다시 보내면 비용이 커서 이후 배치부터는 상태값(`status`/`toBeValue`/`updatedAt`)만 갱신하는 축약 페이로드로 바꿔 처리했다.
- 아티팩트를 다시 게시(publish)하기 전에는 반드시 현재 게시본 전체를 한 줄도 빠짐없이 읽어야 한다(플랫폼이 "이 버전을 열람했는지"를 추적함) — 부분만 읽고 게시하면 거부된다.
