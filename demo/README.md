# 클라우드 데모 (Artifact)

`wafer-spec-console.html`은 백엔드의 검증 로직(`backend/app/services/rules/max_value_by_group_rule.py`)과
집계 로직(`backend/app/services/aggregation.py`)을 브라우저에서 그대로 재현한 단일 HTML 데모입니다.
FastAPI 백엔드가 아니라 Claude Artifact(정적 페이지 + 실시간 공유 저장소 `db` 캐패빌리티)로 배포되어
로그인/설치 없이 링크만으로 열어볼 수 있습니다.

- 배포 링크: https://claude.ai/code/artifact/bff7ce68-9ec0-4b6e-a8fc-1569d3cd9c18
- 질의응답/수정 이력은 Artifact의 `db` 캐패빌리티(실시간 공유 문서 저장소)에 기록되어, 새로고침하거나
  다른 사람이 열어도 유지됩니다. 저장소에 연결하지 못하면 이 브라우저 세션에서만 유지되는 로컬 모드로
  자동 전환됩니다.
- 이 파일을 수정한 뒤 다시 배포하려면 Artifact 퍼블리시 도구로 같은 URL에 재배포하면 됩니다
  (이 리포지토리 자체에는 배포 기능이 없고, 이 파일은 소스 보관 + 재현용입니다).

데모에 쓰인 값은 `backend/scripts/generate_demo_data.py`가 만드는 실제 업로드용 엑셀과 동일한 수치를
쓰도록 맞춰뒀습니다 (둘 중 하나를 바꾸면 다른 쪽도 함께 맞춰주세요).

## 여러 명이 동시에 쓰는 워크플로우 데모 — `spec-qa-workflow.html`

`wafer-spec-console.html`이 검증·집계 로직만 보여주는 정적 미리보기라면, `spec-qa-workflow.html`은
백엔드에 구현된 **역할 기반(관리자/기술팀 담당자/설계사) 질의응답 워크플로우**(자동/수동 2트랙 승인,
SUMMARY 대시보드, GCS 종수, 담당자 전환 시 자동 필터링 등)를 같은 방식(Claude Artifact + `db`
캐패빌리티)으로 브라우저에 재현한, 여러 사람이 동시에 열어 실시간으로 함께 쓰도록 만든 버전입니다.

- 배포 링크: https://claude.ai/code/artifact/fb3bc871-7c09-439d-88cd-0a6d971ef58c
- 같은 조직에 로그인한 사용자 전원이 이 링크로 들어와 상단에서 자기 이름(사용자 관리 화면에서 미리
  등록)을 선택하면, 대시보드/SUMMARY/질의응답 데이터가 그 사람의 역할·담당 대공정(또는 공종)에 맞춰
  자동 필터링되고, 업로드는 관리자 계정에서만 열립니다. 질의 승인/값 수정/제원표 업로드는 모두 Artifact
  의 공유 `db` 저장소에 실시간으로 반영되어 다른 뷰어에게도 즉시 보입니다.
- 실제 FastAPI 백엔드보다 검증 규칙 범위(성상별 유량 OVER, 성상명 표준화·별칭 교정)가 단순화되어 있고
  검증 규칙 CRUD 화면은 없습니다 — 이 프로젝트의 실제 배포판(백엔드+프론트엔드, PR 참고)이 정식
  구현이고, 이 Artifact는 서버 호스팅 없이 여러 명이 같은 워크플로우를 바로 체험/운영해 볼 수 있는
  경량 버전입니다.
- 재배포 방법은 위 `wafer-spec-console.html`과 동일합니다 (Artifact 퍼블리시 도구로 같은 URL에 재배포).

### 더미 데이터 1,000건 + 제원 DB 탭 + 건설코드별 버전 이력

- 시드 고정 PRNG(`fillDummyData`)로 데모 시트 2건(PD000101/102)에 이어 998개 제원표를 추가 생성해
  총 1,000개 건설코드 · 약 11,000개 항목을 채웠습니다. 13개 대공정 전부와 7개 공종 전부에 담당자를
  배정(총 21명)해 담당자 전환 시 자동 필터링이 모든 대공정/공종에서 동작합니다. 이 더미 데이터는
  Artifact의 공유 `db` 저장소에도 배치(batch) 쓰기로 직접 반영해 두어, 누구든 링크를 열면 바로
  1,000건이 채워진 상태로 보입니다.
- 상단 네비게이션에 **"제원 DB"** 탭을 추가했습니다 — 모든 제원표의 항목을 건설코드/버전/대공정/
  대분류/항목명/주요 값/설비모듈 컬럼으로 한 표에 펼쳐 보고, 대공정·대분류 필터와 검색으로 좁혀볼 수
  있는 DB 조회 화면입니다.
- 제원표 문서마다 `ver`(현재 버전)와 `versionHistory`(과거 버전 스냅샷)를 함께 저장합니다. 엑셀
  재업로드로 같은 건설코드가 다시 올라오거나 자동/수동 질의가 승인되어 값이 바뀔 때마다 이전 상태가
  버전으로 보존되고 `ver`가 올라갑니다. 대시보드·제원 DB·제원표 상세(사이드 목록/헤더) 어디서나
  `v{n}` 배지로 보이고, 제원표 상세의 새 **"버전 이력"** 탭에서 각 버전의 항목을 펼쳐볼 수 있습니다.

### PJT(사업장·단계)별 필터링

- 모든 제원표·질의에 `pjt` 필드(예: `P3 ph1`~`ph4`, `P4 ph1`~`ph4`, `P5 ph1`~`ph6`)를 추가하고,
  상단 네비게이션 바에 **PJT 선택** 드롭다운을 새로 넣었습니다 — 특정 PJT를 고르면 대시보드·SUMMARY·
  제원 DB·질의응답이 전부 그 PJT의 데이터만 보여주도록 필터링됩니다(선택하지 않으면 전체 PJT).
  기존에 여러 PJT가 뒤섞여 있던 더미 데이터 1,000건(과 데모 시드 2건)은 전부 `P5 ph1` 기준으로
  통일했고, 이 값은 Artifact의 공유 `db` 저장소에도 배치 쓰기로 동기화해 두었습니다. 제원표 업로드
  화면에도 PJT 선택 필드가 추가되어, 새로 올리는 제원표마다 PJT를 지정할 수 있습니다.

### 질의응답 탭에서 바로 이어지는 대공정별 제원 변경 화면

- "질의응답" 탭 한 화면 안에서 자동 질의 확인부터 제원 변경·최종 DB 반영까지 전부 처리하도록 흐름을
  다시 짰습니다.
  1. **자동 질의**: 대공정 담당 기술팀이 "확인" 버튼을 누르면 특이사항이 없을 때 그 자리에서 TO-BE 값이
     반영되며 종결됩니다. "특이사항 있음"을 누르면 사유를 입력하는 폼이 뜨고, 등록하는 즉시 같은 대상·
     필드를 그대로 들고 **수동 질의로 자동 전환**되어 설계사 판단 단계로 넘어갑니다.
  2. **수동 질의**: 설계사 질의 → 기술팀 회신 → 설계사가 "특이사항 없음"으로 판단하면, 같은 탭 안에
     기술팀이 그 항목의 모든 필드를 직접 고쳐 값을 제안하는 **제원 변경 폼**이 나타납니다(값을 바꾼
     필드만 입력하면 되고, 성상별 유량 OVER·성상명 표준화 등 검증 규칙을 통과해야 등록됩니다). 설계사가
     최종 확인하면 그 자리에서 DB에 반영됩니다.
  3. **재질의**: 답변·제안 어느 단계에서든 반려하면 직전 단계로 돌아가 다시 답변/제안하도록 재질의가
     반복됩니다.
  4. 기술팀·설계사 권한은 여전히 **대공정/공종별로** 게이팅됩니다 — 본인이 담당하는 대공정의 질의만
     확인·답변·제원변경할 수 있습니다.
- "제원 DB" 탭과 제원표 상세의 "제원 항목" 탭에서는, 질의 승인으로 값이 바뀐 적 있는 필드에 셀음영이
  들어가고 커서를 대면 언제·누가·어떤 값에서 어떤 값으로 바꿨는지 팝업(title)으로 보여줍니다. 새 "제원
  변경" 폼에서도 필드 라벨 옆에 같은 수정 이력 배지가 붙어, 바꾸려는 필드가 이전에도 수정된 적이
  있는지 바로 확인할 수 있습니다.

### 질의 2,000건 규모 데이터 + 재질의 횟수 표시

- 질의응답 데이터를 자동/수동 합쳐 약 2,000건 규모로 다시 구성했습니다. 이 중 정확히 50%(자동 250건 +
  수동 750건 = 1,000건)는 **기술팀이 실제로 제원 DB 값을 수정한** 케이스로, 해당 제원표의 `ver`가
  올라가고 수정 이력(`corrections`)·셀음영·호버 팝업까지 전부 채워진 상태로 반영되어 있습니다. 나머지
  절반은 아직 여러 단계(미답변/답변완료/답변승인/값 제안됨)에 걸쳐 진행 중인 질의로 남겨뒀습니다.
- 답변이나 제안이 반려되어 같은 단계로 되돌아간 "재질의" 케이스도 포함했습니다(수동 질의의 약 20%).
  스레드마다 `requeryCount` 필드로 재질의 횟수를 추적하고, 질의 목록 카드·질의 상세·SUMMARY 통계
  (재질의 발생 질의 건수, 재질의 누적 횟수)에서 바로 보여줍니다. 질의응답 탭에는 "재질의 있는 것만
  보기" 필터도 추가했습니다.
- **동기화 원칙**: DB(제원표/질의/수정 이력) 값이 바뀌면 대시보드·SUMMARY·질의응답·제원 DB 등 모든
  탭이 항상 자동으로 다시 반영되도록 만들어져 있습니다 — 각 페이지는 값을 따로 캐시하지 않고 매 렌더링
  마다 공유 저장소의 최신 상태를 그대로 다시 계산해서 보여줍니다.

### "기술팀 확인 유형" 필터

- 질의응답 탭 필터바에 **기술팀 확인 유형** 드롭다운을 추가했습니다 — 지금 기술팀이 다음에 취해야 할
  조치가 무엇인지 기준으로 질의를 세 가지로 나눠 봅니다.
  1. **제원DB수정이 필요한 항목**: 설계사가 답변 승인까지 마쳐, 기술팀이 이 탭에서 바로 제원 변경 폼을
     제출해야 하는 수동 질의(`ANSWER_APPROVED`).
  2. **서술형 답변 필요한 항목**: 설계사가 새로 올린 수동 질의 중 기술팀의 서술형 회신을 기다리는
     것(`OPEN`).
  3. **그 외 확인필요한 항목**: 자동 질의 중 기술팀의 확인/특이사항 클릭을 기다리는 것(`OPEN`).
  - 설계사 차례로 넘어간 질의(답변완료·값 제안됨)나 이미 종결된 질의는 어느 분류에도 잡히지 않습니다.
  - 질의 목록 카드에도 해당 분류 배지가 함께 표시되어, 필터를 걸지 않아도 한눈에 구분할 수 있습니다.

### 질의 카드·상세에 건설코드+설비모듈 표시 / 검색창

- 질의 목록 카드와 질의 상세의 대상 표(건설코드/필드/AS-IS/TO-BE)에 **설비모듈** 열을 추가해, 어떤
  건설코드의 어떤 설비모듈에 대한 질의인지 항상 건설코드와 함께 바로 보이도록 했습니다. 카드에는
  "건설코드 · 설비모듈"을 요약해 보여주고(대상이 여러 건이면 "N건 외"로 표시), 기술팀의 "제원 변경"
  폼 안내문에도 설비모듈을 함께 적었습니다.
- 필터바에 **검색창**을 추가했습니다 — 건설코드, 설비모듈, 필드명, 질의 제목으로 부분일치 검색되어,
  대공정/공종/유형 드롭다운만으로는 부족할 때 기술팀 담당자가 자신이 찾는 항목을 더 세밀하게 좁혀볼 수
  있습니다(예: "SCRUBBER"로 검색하면 그 설비모듈이 걸린 질의만 남습니다).

### "업무 가이드" 탭 — 플로우차트 매뉴얼

- 상단 네비게이션 맨 앞에 **"업무 가이드"** 탭을 추가했습니다. 처음 이 화면을 쓰는 담당자가 매뉴얼처럼
  참고할 수 있도록, 질의 하나가 등록되고 나서 최종 DB 반영으로 종결되기까지 실제로 거치는 모든 경로를
  플로우차트 한 장에 담았습니다 — AUTO 질의 확인/전환, MANUAL 질의의 서술형 답변·설계사 검토, 재질의로
  반려되어 되돌아가는 두 지점(다시 답변 요청/다시 제안 요청), 그리고 AS-IS 값이 그대로면 기술팀 확인
  한 번으로 즉시 종결되는 단축 경로까지 전부 포함합니다.
  - 도형 색으로 누가 처리할 차례인지 구분합니다(기술팀=청록, 설계사=주황, 진행 중 상태=회색,
    종결=초록). 실선 화살표는 다음 단계로 진행, 주황 점선 화살표는 반려로 인한 재질의를 뜻합니다.
  - 각 상태 박스 문구는 "질의응답" 탭에서 실제로 보이는 상태 칩(미답변/답변완료/답변승인/값
    제안됨/해결됨) 문구와 그대로 대응되어, 화면에서 본 칩이 흐름도의 어느 단계인지 바로 찾을 수
    있습니다.
  - 흐름도 아래에는 번호(①~⑧)에 맞춘 단계별 설명(누가·무엇을·어떤 조건에서 하는지, 게이팅 규칙
    포함)과, 대공정/공종 필터·검색창·재질의 표시·셀음영·PJT 필터 등 화면 기능을 요약한 목록도 함께
    넣었습니다.

### 업무 가이드 — 관리자 편집 + 케이스별 처리 횟수

- **관리자만 흐름도를 편집**할 수 있습니다. "업무 가이드" 탭 상단의 "✏️ 편집 (관리자)" 버튼을 누르면
  (관리자 계정에만 보임) 박스·화살표 문구 17개와 "단계별 설명" 목록을 고칠 수 있는 편집 화면이 열립니다.
  - 단계별 설명은 제목·설명·담당 역할(시스템/기술팀/설계사)을 고치고, ▲▼로 순서를 바꾸고, 삭제하거나
    "+ 단계 추가"로 새 단계를 끼워 넣을 수 있습니다. 문구를 고치면 위 흐름도 미리보기가 그 자리에서
    바뀌어 저장 전에 확인할 수 있습니다.
  - "저장"을 누르면 `guide_config` 문서로 Artifact의 공유 `db` 저장소에 반영되어 모든 뷰어에게 실시간
    동기화됩니다(마지막 수정자·시각도 함께 표시). 관리자가 아니면 편집 버튼 자체가 보이지 않습니다.
  - 흐름도의 **도형 배치·연결(어느 상태에서 어느 상태로 가는지)은 고정**되어 있습니다 — 이는 실제
    코드의 상태 머신(자동 확인/전환, 서술형 답변, 답변승인·재질의, 값 확인·제안, 최종확인·재질의)을
    그대로 반영한 것이라, 문구만 관리자가 자유롭게 고쳐도 프로세스 자체의 정확성(실제 업무 로직과의
    동기화)은 항상 유지됩니다.
- **처리 현황 — 케이스별 횟수** 섹션을 추가해, 기술팀·설계사가 각 케이스를 실제로 몇 번 처리했는지
  보여줍니다(AUTO 확인/전환, 서술형 답변, 값 확인·제안, 답변승인·최종확인, 답변/제안 재질의 등 10개
  케이스). 별도 로그를 쌓는 게 아니라 질의 문서에 이미 있는 필드(상태값·재질의 횟수·수정 이력)를 그
  자리에서 다시 계산하므로, 질의 데이터가 바뀔 때마다 항상 실제 처리 현황과 일치합니다.

### 답변승인 단계: 값이 안 바뀌면 확인 한 번으로 바로 종결

- 설계사가 "특이사항 없음"으로 답변을 승인한 직후(답변승인 단계)에는, 예전처럼 항목의 모든 필드를
  편집 가능한 입력창으로 바로 보여주지 않습니다. 대신 **"확인 (AS-IS 값 그대로 확정 · DB 반영)"** 과
  **"값 변경이 필요합니다"** 두 버튼만 먼저 보여줍니다.
  - AS-IS 값 자체가 이미 맞다면 **확인 버튼 한 번**으로 바로 종결됩니다 — 설계사가 이미 답변을
    승인했으므로 값 제안 → 재승인의 두 단계를 다시 거치지 않습니다(값이 안 바뀌므로 수정 이력도
    남기지 않습니다).
  - 실제로 값을 바꿔야 할 때만 "값 변경이 필요합니다"를 눌러 필드 편집 폼을 펼치고, 기존과 동일하게
    제원 변경 제안 → 설계사 최종 확인 → DB 반영 순서로 처리합니다.

### 질의응답 탭 기본값: 미해결만 보기

- 질의응답 탭에 처음 들어가면(또는 담당 대공정/공종 스코프가 풀려도) **"미해결만 보기"가 기본으로
  켜져** 있어 해결됨/반려됨 질의는 목록에서 자동으로 빠집니다. 해결된 질의까지 포함해서 다시 보려면
  필터바의 "미해결만 보기" 체크를 해제하면 됩니다 — 별도 조작 없이 그 즉시 전체 이력이 다시 보입니다.
