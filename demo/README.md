# 클라우드 데모 (Artifact)

`wafer-spec-console.html`은 백엔드의 검증 로직(`backend/app/services/rules/max_value_by_group_rule.py`)과
집계 로직(`backend/app/services/aggregation.py`)을 브라우저에서 그대로 재현한 단일 HTML 데모입니다.
FastAPI 백엔드가 아니라 Claude Artifact(정적 페이지 + 실시간 공유 저장소 `db` 캐패빌리티)로 배포되어
로그인/설치 없이 링크만으로 열어볼 수 있습니다.

- 배포 링크: https://claude.ai/code/artifact/bff7ce68-9ec0-4b6e-a8fc-1569d3cd9c18
- 질의응답/수정 이력은 Artifact의 `db` 캐패빌리티(실시간 공유 문서 저장소)에 기록되어, 새로고침하거나
  다른 사람이 열어도 유지됩니다. 저장소에 연결하지 못하면 이 브라우저 세션에서만 유지되는 로컬 모드로
  자동 전환됩니다.
- 이 파일을 수정한 뒤 다시 배포하려면 Artifact 퍼블리시 도구로 같은 URL에 재배포하면 됩니다
  (이 리포지토리 자체에는 배포 기능이 없고, 이 파일은 소스 보관 + 재현용입니다).

데모에 쓰인 값은 `backend/scripts/generate_demo_data.py`가 만드는 실제 업로드용 엑셀과 동일한 수치를
쓰도록 맞춰뒀습니다 (둘 중 하나를 바꾸면 다른 쪽도 함께 맞춰주세요).

## 여러 명이 동시에 쓰는 워크플로우 데모 — `spec-qa-workflow.html`

`wafer-spec-console.html`이 검증·집계 로직만 보여주는 정적 미리보기라면, `spec-qa-workflow.html`은
백엔드에 구현된 **역할 기반(관리자/기술팀 담당자/설계사) 질의응답 워크플로우**(자동/수동 2트랙 승인,
SUMMARY 대시보드, GCS 종수, 담당자 전환 시 자동 필터링 등)를 같은 방식(Claude Artifact + `db`
캐패빌리티)으로 브라우저에 재현한, 여러 사람이 동시에 열어 실시간으로 함께 쓰도록 만든 버전입니다.

- 배포 링크: https://claude.ai/code/artifact/fb3bc871-7c09-439d-88cd-0a6d971ef58c
- 같은 조직에 로그인한 사용자 전원이 이 링크로 들어와 상단에서 자기 이름(사용자 관리 화면에서 미리
  등록)을 선택하면, 대시보드/SUMMARY/질의응답 데이터가 그 사람의 역할·담당 대공정(또는 공종)에 맞춰
  자동 필터링되고, 업로드는 관리자 계정에서만 열립니다. 질의 승인/값 수정/제원표 업로드는 모두 Artifact
  의 공유 `db` 저장소에 실시간으로 반영되어 다른 뷰어에게도 즉시 보입니다.
- 실제 FastAPI 백엔드보다 검증 규칙 범위(성상별 유량 OVER, 성상명 표준화·별칭 교정)가 단순화되어 있고
  검증 규칙 CRUD 화면은 없습니다 — 이 프로젝트의 실제 배포판(백엔드+프론트엔드, PR 참고)이 정식
  구현이고, 이 Artifact는 서버 호스팅 없이 여러 명이 같은 워크플로우를 바로 체험/운영해 볼 수 있는
  경량 버전입니다.
- 재배포 방법은 위 `wafer-spec-console.html`과 동일합니다 (Artifact 퍼블리시 도구로 같은 URL에 재배포).

### 더미 데이터 1,000건 + 제원 DB 탭 + 건설코드별 버전 이력

- 시드 고정 PRNG(`fillDummyData`)로 데모 시트 2건(PD000101/102)에 이어 998개 제원표를 추가 생성해
  총 1,000개 건설코드 · 약 11,000개 항목을 채웠습니다. 13개 대공정 전부와 7개 공종 전부에 담당자를
  배정(총 21명)해 담당자 전환 시 자동 필터링이 모든 대공정/공종에서 동작합니다. 이 더미 데이터는
  Artifact의 공유 `db` 저장소에도 배치(batch) 쓰기로 직접 반영해 두어, 누구든 링크를 열면 바로
  1,000건이 채워진 상태로 보입니다.
- 상단 네비게이션에 **"제원 DB"** 탭을 추가했습니다 — 모든 제원표의 항목을 건설코드/버전/대공정/
  대분류/항목명/주요 값/설비모듈 컬럼으로 한 표에 펼쳐 보고, 대공정·대분류 필터와 검색으로 좁혀볼 수
  있는 DB 조회 화면입니다.
- 제원표 문서마다 `ver`(현재 버전)와 `versionHistory`(과거 버전 스냅샷)를 함께 저장합니다. 엑셀
  재업로드로 같은 건설코드가 다시 올라오거나 자동/수동 질의가 승인되어 값이 바뀔 때마다 이전 상태가
  버전으로 보존되고 `ver`가 올라갑니다. 대시보드·제원 DB·제원표 상세(사이드 목록/헤더) 어디서나
  `v{n}` 배지로 보이고, 제원표 상세의 새 **"버전 이력"** 탭에서 각 버전의 항목을 펼쳐볼 수 있습니다.

### PJT(사업장·단계)별 필터링

- 모든 제원표·질의에 `pjt` 필드(예: `P3 ph1`~`ph4`, `P4 ph1`~`ph4`, `P5 ph1`~`ph6`)를 추가하고,
  상단 네비게이션 바에 **PJT 선택** 드롭다운을 새로 넣었습니다 — 특정 PJT를 고르면 대시보드·SUMMARY·
  제원 DB·질의응답이 전부 그 PJT의 데이터만 보여주도록 필터링됩니다(선택하지 않으면 전체 PJT).
  기존에 여러 PJT가 뒤섞여 있던 더미 데이터 1,000건(과 데모 시드 2건)은 전부 `P5 ph1` 기준으로
  통일했고, 이 값은 Artifact의 공유 `db` 저장소에도 배치 쓰기로 동기화해 두었습니다. 제원표 업로드
  화면에도 PJT 선택 필드가 추가되어, 새로 올리는 제원표마다 PJT를 지정할 수 있습니다.

### 질의응답 탭에서 바로 이어지는 대공정별 제원 변경 화면

- "질의응답" 탭 한 화면 안에서 자동 질의 확인부터 제원 변경·최종 DB 반영까지 전부 처리하도록 흐름을
  다시 짰습니다.
  1. **자동 질의**: 대공정 담당 기술팀이 "확인" 버튼을 누르면 특이사항이 없을 때 그 자리에서 TO-BE 값이
     반영되며 종결됩니다. "특이사항 있음"을 누르면 사유를 입력하는 폼이 뜨고, 등록하는 즉시 같은 대상·
     필드를 그대로 들고 **수동 질의로 자동 전환**되어 설계사 판단 단계로 넘어갑니다.
  2. **수동 질의**: 설계사 질의 → 기술팀 회신 → 설계사가 "특이사항 없음"으로 판단하면, 같은 탭 안에
     기술팀이 그 항목의 모든 필드를 직접 고쳐 값을 제안하는 **제원 변경 폼**이 나타납니다(값을 바꾼
     필드만 입력하면 되고, 성상별 유량 OVER·성상명 표준화 등 검증 규칙을 통과해야 등록됩니다). 설계사가
     최종 확인하면 그 자리에서 DB에 반영됩니다.
  3. **재질의**: 답변·제안 어느 단계에서든 반려하면 직전 단계로 돌아가 다시 답변/제안하도록 재질의가
     반복됩니다.
  4. 기술팀·설계사 권한은 여전히 **대공정/공종별로** 게이팅됩니다 — 본인이 담당하는 대공정의 질의만
     확인·답변·제원변경할 수 있습니다.
- "제원 DB" 탭과 제원표 상세의 "제원 항목" 탭에서는, 질의 승인으로 값이 바뀐 적 있는 필드에 셀음영이
  들어가고 커서를 대면 언제·누가·어떤 값에서 어떤 값으로 바꿨는지 팝업(title)으로 보여줍니다. 새 "제원
  변경" 폼에서도 필드 라벨 옆에 같은 수정 이력 배지가 붙어, 바꾸려는 필드가 이전에도 수정된 적이
  있는지 바로 확인할 수 있습니다.

### 질의 2,000건 규모 데이터 + 재질의 횟수 표시

- 질의응답 데이터를 자동/수동 합쳐 약 2,000건 규모로 다시 구성했습니다. 이 중 정확히 50%(자동 250건 +
  수동 750건 = 1,000건)는 **기술팀이 실제로 제원 DB 값을 수정한** 케이스로, 해당 제원표의 `ver`가
  올라가고 수정 이력(`corrections`)·셀음영·호버 팝업까지 전부 채워진 상태로 반영되어 있습니다. 나머지
  절반은 아직 여러 단계(미답변/답변완료/답변승인/값 제안됨)에 걸쳐 진행 중인 질의로 남겨뒀습니다.
- 답변이나 제안이 반려되어 같은 단계로 되돌아간 "재질의" 케이스도 포함했습니다(수동 질의의 약 20%).
  스레드마다 `requeryCount` 필드로 재질의 횟수를 추적하고, 질의 목록 카드·질의 상세·SUMMARY 통계
  (재질의 발생 질의 건수, 재질의 누적 횟수)에서 바로 보여줍니다. 질의응답 탭에는 "재질의 있는 것만
  보기" 필터도 추가했습니다.
- **동기화 원칙**: DB(제원표/질의/수정 이력) 값이 바뀌면 대시보드·SUMMARY·질의응답·제원 DB 등 모든
  탭이 항상 자동으로 다시 반영되도록 만들어져 있습니다 — 각 페이지는 값을 따로 캐시하지 않고 매 렌더링
  마다 공유 저장소의 최신 상태를 그대로 다시 계산해서 보여줍니다.

### "기술팀 확인 유형" 필터

- 질의응답 탭 필터바에 **기술팀 확인 유형** 드롭다운을 추가했습니다 — 지금 기술팀이 다음에 취해야 할
  조치가 무엇인지 기준으로 질의를 세 가지로 나눠 봅니다.
  1. **제원DB수정이 필요한 항목**: 설계사가 답변 승인까지 마쳐, 기술팀이 이 탭에서 바로 제원 변경 폼을
     제출해야 하는 수동 질의(`ANSWER_APPROVED`).
  2. **서술형 답변 필요한 항목**: 설계사가 새로 올린 수동 질의 중 기술팀의 서술형 회신을 기다리는
     것(`OPEN`).
  3. **그 외 확인필요한 항목**: 자동 질의 중 기술팀의 확인/특이사항 클릭을 기다리는 것(`OPEN`).
  - 설계사 차례로 넘어간 질의(답변완료·값 제안됨)나 이미 종결된 질의는 어느 분류에도 잡히지 않습니다.
  - 질의 목록 카드에도 해당 분류 배지가 함께 표시되어, 필터를 걸지 않아도 한눈에 구분할 수 있습니다.

### 질의 카드·상세에 건설코드+설비모듈 표시 / 검색창

- 질의 목록 카드와 질의 상세의 대상 표(건설코드/필드/AS-IS/TO-BE)에 **설비모듈** 열을 추가해, 어떤
  건설코드의 어떤 설비모듈에 대한 질의인지 항상 건설코드와 함께 바로 보이도록 했습니다. 카드에는
  "건설코드 · 설비모듈"을 요약해 보여주고(대상이 여러 건이면 "N건 외"로 표시), 기술팀의 "제원 변경"
  폼 안내문에도 설비모듈을 함께 적었습니다.
- 필터바에 **검색창**을 추가했습니다 — 건설코드, 설비모듈, 필드명, 질의 제목으로 부분일치 검색되어,
  대공정/공종/유형 드롭다운만으로는 부족할 때 기술팀 담당자가 자신이 찾는 항목을 더 세밀하게 좁혀볼 수
  있습니다(예: "SCRUBBER"로 검색하면 그 설비모듈이 걸린 질의만 남습니다).

### "업무 가이드" 탭 — 플로우차트 매뉴얼

- 상단 네비게이션 맨 앞에 **"업무 가이드"** 탭을 추가했습니다. 처음 이 화면을 쓰는 담당자가 매뉴얼처럼
  참고할 수 있도록, 질의 하나가 등록되고 나서 최종 DB 반영으로 종결되기까지 실제로 거치는 모든 경로를
  플로우차트 한 장에 담았습니다 — AUTO 질의 확인/전환, MANUAL 질의의 서술형 답변·설계사 검토, 재질의로
  반려되어 되돌아가는 두 지점(다시 답변 요청/다시 제안 요청), 그리고 AS-IS 값이 그대로면 기술팀 확인
  한 번으로 즉시 종결되는 단축 경로까지 전부 포함합니다.
  - 도형 색으로 누가 처리할 차례인지 구분합니다(기술팀=청록, 설계사=주황, 진행 중 상태=회색,
    종결=초록). 실선 화살표는 다음 단계로 진행, 주황 점선 화살표는 반려로 인한 재질의를 뜻합니다.
  - 각 상태 박스 문구는 "질의응답" 탭에서 실제로 보이는 상태 칩(미답변/답변완료/답변승인/값
    제안됨/해결됨) 문구와 그대로 대응되어, 화면에서 본 칩이 흐름도의 어느 단계인지 바로 찾을 수
    있습니다.
  - 흐름도 아래에는 번호(①~⑧)에 맞춘 단계별 설명(누가·무엇을·어떤 조건에서 하는지, 게이팅 규칙
    포함)과, 대공정/공종 필터·검색창·재질의 표시·셀음영·PJT 필터 등 화면 기능을 요약한 목록도 함께
    넣었습니다.

### 업무 가이드 — 관리자 편집 + 케이스별 처리 횟수

- **관리자만 흐름도를 편집**할 수 있습니다. "업무 가이드" 탭 상단의 "✏️ 편집 (관리자)" 버튼을 누르면
  (관리자 계정에만 보임) 박스·화살표 문구 17개와 "단계별 설명" 목록을 고칠 수 있는 편집 화면이 열립니다.
  - 단계별 설명은 제목·설명·담당 역할(시스템/기술팀/설계사)을 고치고, ▲▼로 순서를 바꾸고, 삭제하거나
    "+ 단계 추가"로 새 단계를 끼워 넣을 수 있습니다. 문구를 고치면 위 흐름도 미리보기가 그 자리에서
    바뀌어 저장 전에 확인할 수 있습니다.
  - "저장"을 누르면 `guide_config` 문서로 Artifact의 공유 `db` 저장소에 반영되어 모든 뷰어에게 실시간
    동기화됩니다(마지막 수정자·시각도 함께 표시). 관리자가 아니면 편집 버튼 자체가 보이지 않습니다.
  - 흐름도의 **도형 배치·연결(어느 상태에서 어느 상태로 가는지)은 고정**되어 있습니다 — 이는 실제
    코드의 상태 머신(자동 확인/전환, 서술형 답변, 답변승인·재질의, 값 확인·제안, 최종확인·재질의)을
    그대로 반영한 것이라, 문구만 관리자가 자유롭게 고쳐도 프로세스 자체의 정확성(실제 업무 로직과의
    동기화)은 항상 유지됩니다.
- **처리 현황 — 케이스별 횟수** 섹션을 추가해, 기술팀·설계사가 각 케이스를 실제로 몇 번 처리했는지
  보여줍니다(AUTO 확인/전환, 서술형 답변, 값 확인·제안, 답변승인·최종확인, 답변/제안 재질의 등 10개
  케이스). 별도 로그를 쌓는 게 아니라 질의 문서에 이미 있는 필드(상태값·재질의 횟수·수정 이력)를 그
  자리에서 다시 계산하므로, 질의 데이터가 바뀔 때마다 항상 실제 처리 현황과 일치합니다.

### 성상명·자재명 표준 콤보박스 + 최초 수동 질의 빠른 처리

- **성상명·자재명 표준 콤보박스**: "제원 변경" 화면(질의응답 탭 안)에서 성상명·자재명 필드는 더 이상
  자유 텍스트가 아니라 대분류별 표준 목록(GAS/AIR는 N2/O2/AR/CDA/HE/H2, WATER는 PCW/ICW/RCW,
  SPECIALITY GAS·폐액은 자재명 목록 등)에서만 고를 수 있는 콤보박스입니다. 더미 데이터 생성 로직과
  같은 목록을 그대로 참조해 표준값이 한 곳에서만 관리됩니다. 기존 값이 표준 목록에 없는 비표준
  값이면 "(현재값·비표준)"으로 맨 위에 얹어 보여줘 바로 표준값으로 바꿀 수 있게 했습니다.
- **최초 수동 질의(OPEN) 빠른 처리**: 설계사가 막 등록한 수동 질의에 기술팀이 답변할 때, 화면에
  두 가지 버튼이 나란히 보입니다.
  1. **"AS-IS 값 승인 (특이사항 없음)"** — AS-IS 값 자체가 맞으면 서술형으로 타이핑하지 않아도 버튼
     한 번으로 답변완료(TECH_ANSWERED) 상태로 넘어가 설계사 검토를 기다립니다.
  2. **"제원 변경 제안 (설계사에게 값 제안)"** — 값을 바로 고쳐야 하는 게 명확하면 답변완료·답변승인
     두 단계를 건너뛰고 그 자리에서 값을 제안해 곧장 "값 제안됨" 상태로 넘어가고, 설계사 최종확인만
     받으면 됩니다(제안 폼의 성상명·자재명도 위와 같은 표준 콤보박스입니다). 그 아래에는 기존처럼
     서술형으로 답변할 수 있는 칸도 그대로 남겨뒀습니다.
  - 이 빠른 경로도 반드시 설계사의 최종확인을 한 번은 거쳐야 DB에 반영되므로, "모든 값 변경은 설계사
    확인을 거친다"는 원칙은 그대로 유지됩니다. 업무 가이드 탭의 흐름도에도 이 경로가 굵은 청록
    화살표(②→⑦)로 추가되어 있고, "처리 현황" 통계도 답변승인을 실제로 거쳤는지 여부를 정확히
    구분해서 셉니다(빠른 경로로 건너뛴 건은 "답변승인" 건수에 잘못 포함되지 않습니다).

### AUTO 질의에도 같은 "기술팀 값 제안(빠른 처리)" 추가

- 최초 수동 질의(OPEN)에 이어, **AUTO 질의(OPEN)**에도 같은 패턴의 빠른 경로를 추가했습니다. 기존
  "확인(특이사항 없음)" / "특이사항 있음(수동 전환)" 두 버튼 사이에 **"값 제안 (빠른 처리)"** 버튼이
  새로 생겨, 시스템이 계산한 TO-BE 값이 아니라 기술팀이 판단하기에 다른 값이 맞을 때 사유 설명 없이
  그 값을 직접 입력해 제안할 수 있습니다(성상명·자재명은 여기서도 표준 콤보박스).
- 제안하면 수동 질의로 전환되면서 답변완료·답변승인 단계 없이 곧장 "값 제안됨"으로 시작해 설계사
  최종확인만 받으면 됩니다 — 최초 수동 질의의 ②→⑦ 빠른 경로와 완전히 같은 원리이며, 여기서도 DB
  반영 전 설계사 확인이 최소 한 번은 반드시 있어야 하는 원칙은 유지됩니다.
- 업무 가이드 탭 흐름도에 ①→⑦ 화살표(청록, ②→⑦과 대칭)로 추가했고, "AUTO → 수동 전환" 처리 현황
  통계 라벨도 특이사항 전환과 값 제안 전환을 모두 포함하도록 문구를 다듬었습니다.

### 답변승인 단계: 값이 안 바뀌면 확인 한 번으로 바로 종결

- 설계사가 "특이사항 없음"으로 답변을 승인한 직후(답변승인 단계)에는, 예전처럼 항목의 모든 필드를
  편집 가능한 입력창으로 바로 보여주지 않습니다. 대신 **"확인 (AS-IS 값 그대로 확정 · DB 반영)"** 과
  **"값 변경이 필요합니다"** 두 버튼만 먼저 보여줍니다.
  - AS-IS 값 자체가 이미 맞다면 **확인 버튼 한 번**으로 바로 종결됩니다 — 설계사가 이미 답변을
    승인했으므로 값 제안 → 재승인의 두 단계를 다시 거치지 않습니다(값이 안 바뀌므로 수정 이력도
    남기지 않습니다).
  - 실제로 값을 바꿔야 할 때만 "값 변경이 필요합니다"를 눌러 필드 편집 폼을 펼치고, 기존과 동일하게
    제원 변경 제안 → 설계사 최종 확인 → DB 반영 순서로 처리합니다.

### 질의응답 탭 기본값: 미해결만 보기

- 질의응답 탭에 처음 들어가면(또는 담당 대공정/공종 스코프가 풀려도) **"미해결만 보기"가 기본으로
  켜져** 있어 해결됨/반려됨 질의는 목록에서 자동으로 빠집니다. 해결된 질의까지 포함해서 다시 보려면
  필터바의 "미해결만 보기" 체크를 해제하면 됩니다 — 별도 조작 없이 그 즉시 전체 이력이 다시 보입니다.

### 제원 DB 탭 엑셀 다운로드 (전체 / 변경 이력만)

- "제원 DB" 탭 상단에 엑셀(.xlsx) 다운로드 버튼 두 개를 추가했습니다. 둘 다 상단 **PJT 선택**으로
  좁힌 범위를 기준으로 삼고(대공정/대분류/검색 필터는 화면 표시에만 적용되고 다운로드 범위에는 영향을
  주지 않습니다), Artifact의 `downloads` 캐패빌리티로 뷰어에게 파일 저장을 요청합니다(이미 업로드
  파서에서 쓰던 SheetJS `xlsx.full.min.js`로 워크북을 그 자리에서 만듭니다).
  1. **"{PJT} 제원DB 전체 엑셀 다운로드"** — 선택한 PJT의 모든 제원표·항목을 건설코드/버전/대공정/
     대분류/항목구분/항목명/스펙 필드(유량·배관수량·압력·배관재질·전력값·부하전류·전압·차단기전류·
     실사용량·풍량·포트 수량)/설비모듈 컬럼으로 펼쳐 담습니다. 화면 표의 500건 표시 제한과 무관하게
     범위 전체를 담습니다.
  2. **"변경된 사항만 엑셀 다운로드 (N건)"** — 그중 질의 승인으로 값이 바뀐 적 있는 수정 이력
     (`corrections`)만 최신순으로 담습니다(건설코드/버전/대공정/대분류/항목명/필드/변경 전·후 값/
     자동·수동 처리유형/처리자/일시). 범위 안에 변경 이력이 하나도 없으면 버튼이 비활성화됩니다.
  - `downloads` 캐패빌리티를 못 쓰는 화면(다운로드를 지원하지 않는 뷰어 등)에서는 안내 문구만 보이고
    버튼을 눌러도 다운로드가 일어나지 않습니다.

### "그래프 만들기" 탭 — 피벗 표/그래프 + 엑셀·PNG 다운로드 + PPT 붙여넣기

- 상단 네비게이션에 **"그래프 만들기"** 탭을 추가했습니다. 엑셀 피벗테이블처럼 **행(Rows)/열
  (Columns)/값(Values)/집계 방식**을 드롭다운으로 고르면 표와 그래프(막대/원형)가 그 자리에서 함께
  만들어집니다.
  - 행·열 후보는 PJT/대공정/대분류/항목명(성상명·전원종류·자재명)/설비모듈/건설코드, 값 후보는 제원
    스펙 필드(유량·전력값·실사용량 등) 또는 "건수(개수)"이며, 집계는 합계/평균/개수/최대/최소 중
    고를 수 있습니다.
  - 데이터 범위는 "제원 DB" 탭과 동일하게 상단 **PJT 선택**을 그대로 따르고, 탭 자체의 대공정/대분류
    필터로 한 번 더 좁힐 수 있습니다.
  - 행이 40개, 열(계열)이 8개를 넘으면 중요도(집계값 크기) 상위 항목만 남기고 나머지는 자동으로
    "기타"로 묶어, 건설코드처럼 값이 많은 필드를 골라도 표·그래프가 항상 읽을 수 있는 크기를
    유지합니다. 그래프 계열 색상은 dataviz 스킬의 검증된 카테고리 8슬롯 팔레트를 그대로 써서 라이트/
    다크 모드 모두 색맹 안전성이 검증된 순서를 따릅니다.
  - 원형그래프는 열을 선택하지 않았을 때만(행 하나만으로 슬라이스를 나눌 때) 고를 수 있습니다.
- 다운로드·복사 버튼 3종을 그래프 위에 두었습니다.
  1. **표 엑셀 다운로드** — 기존 제원 DB 탭과 같은 `downloads` 캐패빌리티로 피벗 표를 `.xlsx`로
     저장합니다.
  2. **그래프 이미지(PNG) 다운로드** — 화면의 그래프(SVG)를 PNG로 변환해 저장합니다.
  3. **"표+그래프 복사 (PPT/워드에 붙여넣기)"** — 매번 엑셀을 내려받아 복사·붙여넣기 하는 수고를
     줄이기 위해 추가했습니다. 표와 그래프 이미지를 함께 클립보드에 담아, PowerPoint나 워드에
     **Ctrl+V** 한 번으로 표는 표로, 그래프는 그림으로 그대로 붙여넣어집니다(브라우저 Clipboard API를
     먼저 쓰고, 이 화면에서 막히면 옛 `execCommand('copy')` 방식으로 한 번 더 시도합니다 — 그마저 안
     되는 브라우저/환경에서는 엑셀·PNG 다운로드로 대신 받을 수 있다는 안내가 뜹니다).

### "그래프 만들기" 탭 — 대분류 필터에 맞춰 값(Values) 자동 연동

- 대분류(필터)를 고르면 값(Values) 드롭다운도 그 대분류의 제원집계 로직(`AGG_SPECS` — SUMMARY 탭
  "대분류별 총량 집계"와 같은 기준)이 실제로 쓰는 필드만 남도록 자동으로 좁혀집니다. 예: POWER→전력값만,
  폐액→실사용량만, GAS/AIR→배관수량·유량만. 대분류를 "전체"로 두면 기존처럼 모든 필드를 고를 수
  있습니다. 이미 골라둔 값이 새 목록 밖이면(예: 유량 선택 중 대분류를 POWER로 바꾼 경우) 첫 후보로
  자동 전환됩니다.
- 이 보정 로직(`normalizePivotState()`)은 화면과 아래 AI 챗봇이 공유합니다 — 챗봇이 자연어로 만든
  조건도 항상 같은 규칙을 거쳐 화면과 동일한 결과를 냅니다.
- 계산값 필드가 2개인 대분류(GAS/AIR·WATER·WASTE WATER·EXHAUST)는 원본 필드(예: 배관수량, 유량)
  각각뿐 아니라, 그 대분류의 제원집계 로직 그대로 두 필드를 곱한 **집계값**(예: "배관수량×유량
  집계값(SLPM)")도 값(Values) 맨 위에 추가로 고를 수 있습니다(`itemAggValue`/`pivotMeasureLabel`).
  이 집계값을 행(Rows)=항목명(성상명/전원종류/자재명)으로 묶어 합계 집계하면 SUMMARY 탭 "대분류별
  총량 집계" 카드와 정확히 같은 숫자가 나옵니다 — 같은 `AGG_SPECS`를 쓰는 `computeAggregation()`의
  그룹 합산 전 단계(한 행의 amount) 계산을 그대로 재사용하기 때문입니다. 필드가 1개뿐인 대분류
  (POWER·UPW·CHEMICAL·SPECIALITY GAS·폐액)는 그 필드 자체가 이미 집계값과 같으므로 따로 만들지
  않습니다. AI 챗봇도 "제원집계"·"총량"·"집계값" 같은 표현이 나오면 이 필드를 고르도록 프롬프트에
  안내되어 있습니다.

### 막대·원형 그래프에 값 라벨 직접 표기 (소수점 없이 정수로)

- 막대그래프는 각 막대 위(음수면 아래)에, 원형그래프는 슬라이스가 충분히 클 때(전체의 4.5% 이상)
  안쪽에 값을 직접 숫자로 표기합니다 — 축 눈금도 포함해 그래프 안의 모든 숫자는 소수점 없이 정수로
  반올림해 보여줍니다(표/엑셀 다운로드는 기존처럼 정밀도를 유지합니다. `fmtChartVal` vs `fmtPivotVal`).
  원형그래프 라벨은 팔레트 어느 색 위에서도 읽히도록 흰 글자 + 어두운 외곽선(halo)으로 그렸고, 슬라이스가
  8% 이상이면 비율(%)도 함께 보여줍니다. 막대가 너무 촘촘해(계열이 많아 한 막대 폭이 14px 미만) 라벨이
  겹칠 상황에서만 생략합니다(선택적 라벨 원칙).

### 우측 하단 AI 챗봇 — 자연어로 물어보면 표+그래프를 바로 만들어 보여줌

- 모든 탭 우측 하단에 떠 있는 💬 버튼으로 채팅창을 엽니다. Artifact의 `sample` 캐패빌리티(뷰어 본인의
  Claude 계정으로 Claude에게 물어보는 기능)를 써서, "P5 ph1의 GAS/AIR의 성상별 제원집계를 표랑
  그래프로 반환해줘" 같은 자연어 질문을 "그래프 만들기" 탭과 같은 피벗 조건(PJT/대공정/대분류/행·열
  기준/값 필드/집계 방식/그래프 종류)으로 해석시킨 뒤, 같은 `computePivot()` 파이프라인으로 표+그래프를
  채팅창 안에 바로 그립니다.
  - 챗봇이 돌려준 값은 런타임에서 검증되지 않으므로, 앱이 알려진 PJT/대공정/대분류/필드/집계 방식
    목록에 맞는지 다시 확인하고(`applyChatParsedToState`) 화면과 같은 보정 규칙(`normalizePivotState`)을
    한 번 더 거칩니다 — 대분류에 안 맞는 값을 챗봇이 잘못 고르는 경우에도 화면과 똑같이 자동 보정됩니다.
  - 각 답변 아래 **"그래프 만들기 탭에서 크게 보기"** 버튼을 누르면, 그 질문 당시의 조건이 그대로
    적용된 채(다른 질문으로 나중에 조건이 바뀌어도 이 버튼은 그 메시지의 조건을 다시 복원합니다)
    "그래프 만들기" 탭으로 이동해 40행·8계열까지 보이는 큰 화면으로 이어 볼 수 있습니다.
  - `sample` 캐패빌리티를 쓸 수 없는 화면(다운로드와 마찬가지로 뷰어에 따라 제공되지 않을 수 있음)에서는
    채팅창은 뜨지만 메시지를 보내면 안내 문구만 나오고, "그래프 만들기" 탭을 직접 쓰라고 안내합니다.

### SUMMARY 탭 — 대분류별 총량 집계에 그래프 + 엑셀 다운로드 + PPT 복사 추가

- "대분류별 총량 집계"의 각 카드(GAS/AIR, POWER, …)에 이제 막대그래프가 함께 그려집니다. 카드마다
  "그래프 만들기" 탭과 같은 데이터 파이프라인(`pivotSourceRows → computePivot`, `pivotMeasureFieldsFor`로
  고른 필드 — 대분류의 제원집계 로직과 동일)을 재사용해 만들었기 때문에, 카드 하단의 "합계" 숫자와
  그래프·표가 항상 정확히 같은 값을 가리킵니다(`summaryCategoryPivot`, `renderSummaryAggCard`).
- 카드마다 버튼 3개가 있습니다: **⬇ 엑셀**(그 대분류의 그룹별 값 + 합계 행을 `.xlsx`로), **⬇ PNG**
  (그래프 이미지를 다운로드), **📋 복사**("그래프 만들기" 탭과 같은 방식으로 표+그래프 이미지를 함께
  클립보드에 담아 PPT/워드에 Ctrl+V로 붙여넣기). 세 버튼 모두 기존 `saveWorkbook`/`svgToPngBlob`/
  `copyPivotToClipboard`를 그대로 재사용합니다 — `copyPivotToClipboard`는 진행 메시지를 보여줄 엘리먼트를
  콜백으로 받도록 바꿔서("그래프 만들기" 탭과 SUMMARY 탭이 서로 다른 메시지 영역을 씁니다) 코드 중복 없이
  양쪽에서 같이 쓸 수 있게 했습니다.
- 패널 상단의 **"⬇ 전체 표 엑셀 다운로드"**는 지금 보이는 모든 대분류 카드의 그룹별 값을 대분류/항목명/
  값/단위 4열로 한 시트에 모아 한 번에 받습니다.
- 제원표 상세의 "총량 집계" 탭(카드 텍스트만 보여주던 기존 화면)은 그대로 두었습니다 — 그래프·다운로드는
  SUMMARY 탭 전용입니다.

### "수동질의 등록" 탭 — 설계사가 검증 이슈 없이도 AS-IS/TO-BE 수동 질의를 직접 올릴 수 있음

- 지금까지 설계사가 수동 질의를 올리는 유일한 경로는 "검증 결과" 탭에 뜬 이슈에 딸린 "질문하기"
  버튼뿐이었습니다. 새 **"수동질의 등록"** 탭에서는 이슈가 없어도 설계사(또는 관리자)가 대공정 →
  건설코드 → 설비모듈 순서로 대상을 직접 골라 곧장 수동(SPEC) 질의를 새로 올릴 수 있습니다.
- **대공정·건설코드·설비모듈은 필수 선택값**입니다 — 이 세 값으로 대상 항목을 명확히 좁힌 뒤에야
  다음 단계(같은 설비모듈에 항목이 여럿이면 항목 선택 → 필드 선택)로 넘어갈 수 있어, 어느 항목의
  질의인지 애매해질 여지가 없습니다.
- 필드를 고르면 **AS-IS(현재값)는 제원 DB에서 자동으로 읽어와 그대로 보여주고**, **TO-BE(제안값)**는
  설계사가 직접 입력합니다(성상명·자재명처럼 표준 목록이 있는 필드는 기존 "제원 변경" 화면과 똑같이
  콤보박스로 표준값만 고르게 했습니다). 제출 전 기존 값 제안과 동일한 검증 규칙(`validateCandidate`
  — 성상별 유량 OVER 등)을 한 번 더 통과해야 등록됩니다.
- 대공정을 고르면 그 대공정 **담당 기술팀과 소속(대공정)이 바로 표시**되어(`pickTechLeadFor`), 이
  질의가 누구에게 배정될지 등록 전에 미리 확인할 수 있습니다.
- 등록되는 질의는 기존 질의응답 상태 머신을 그대로 탑니다 — **곧바로 DB에 반영되지 않고 OPEN 상태로
  들어가**, 담당 기술팀이 "질의응답" 탭에서 기존과 동일하게 "AS-IS 값 유지 확인" 또는 "값 제안"으로
  검토해야 최종 반영됩니다(설계사가 적은 TO-BE는 어디까지나 제안값이며, 상태 전이 함수는 하나도 건드리지
  않았습니다). 등록 직후에는 "질의응답" 탭으로 이동해 방금 만든 질의의 AS-IS→TO-BE 표를 바로 보여줍니다.
- 이 탭은 상단 메뉴에서 설계사·관리자 계정에게만 열려 있고(업로드 탭이 관리자 전용인 것과 같은 방식),
  다른 역할이거나 사용자를 선택하지 않은 상태에서는 안내 문구만 보입니다.

### "그래프 만들기" 탭 — 그래프·표에 단위 표기 추가

- 값(Values) 드롭다운, "그래프"/"표" 패널 제목, 그래프 y축 위쪽, 막대·파이 슬라이스 툴팁, 표 헤더까지
  모두 단위가 함께 보입니다(`pivotMeasureUnit`/`chartUnitFor`/`pivotMeasureLabel`). 단위는 새로 지어내지
  않고 항상 `AGG_SPECS`(대분류별 총량 집계가 쓰는 것과 같은 표)를 진실의 원천으로 삼습니다.
  - 대분류를 필터로 고르면 그 대분류의 단위를 그대로 씁니다(예: GAS/AIR→SLPM, POWER→KW).
  - 대분류를 고르지 않았을 때는, 그 필드를 쓰는 모든 대분류의 단위가 전부 같을 때만 단위를 보여줍니다
    (예: 유량은 WATER/WASTE WATER/GAS/AIR 모두 SLPM이라 항상 뜹니다). 대분류마다 단위가 다른 필드
    (배관수량: SLPM/EA, 실사용량: TON/DAY/LITER/DAY)는 대분류를 정하기 전까지는 단위를 보여주지
    않습니다 — 틀린 단위를 보여주는 것보다 안전합니다.
  - `AGG_SPECS`에 아예 없는 필드(압력·배관재질·부하전류·전압·차단기전류)는 이 앱 어디에도 정의된
    단위가 없으므로 지금처럼 단위 없이 표시됩니다.
  - 그래프 축에는 눈금마다 단위를 반복하지 않고(촘촘한 눈금끼리 겹치는 것을 막기 위해) y축 맨 위에
    "(SLPM)"처럼 한 번만 표기합니다. SUMMARY 탭 카드의 미니 그래프와 AI 챗봇 결과 그래프도 같은
    `chartUnitFor`를 함께 써서 동일하게 단위가 보입니다.

### "제원표 업로드" 탭 — 업로드 검수(양식 적합성 리포트) + 파서 유연성 개선

- 업로드 후 결과 영역에 **검수 결과** 박스가 추가됩니다: 인식한 항목 수, 항목명(성상명/전원종류/자재명)이
  없는 항목 수, 대분류가 비어 있는 항목 수, 표준 대분류(`CAT_ORDER`) 목록에 없는 대분류 값과 건수,
  표준 필드명과 달라 원본 문구 그대로 저장한 필드 목록, 검증 규칙(성상별 유량 OVER·표준화) 위반 건수를
  한눈에 보여줍니다(`auditParsedGroups`/`renderUploadAudit`). 문제가 하나도 없으면 "✓ 검수 결과 — 양식에
  맞게 잘 들어왔습니다"만 보입니다.
- **이 리포트는 저장을 막지 않습니다** — 양식이 꼭 맞지 않아도 파서는 그대로 DB화하고, 이 박스는 그
  결과가 얼마나 표준에 가까운지만 알려줍니다. 표준 대분류가 아니거나 낯선 필드명이어도 원본 그대로
  저장되므로(파서가 원래도 관대했습니다), 업로드 후 각 제원표 화면에서 값을 확인·수정하면 됩니다.
- 파서 자체도 더 유연해졌습니다: 헤더 문구가 표준 필드명과 공백만 다를 때(예: "설비 모듈" vs
  "설비모듈")도 같은 필드로 인식해 표준 철자로 저장합니다(`canonicalizeLabel`) — 그래야 이 필드를
  이름으로 직접 참조하는 다른 화면(제원 DB의 설비모듈 표시, "수동질의 등록" 탭의 필드 목록 등)이 그대로
  동작합니다. 숫자 열에 쉼표 천단위 구분자가 섞여 있어도("1,234") 숫자로 인식합니다(`stripThousands`).

### 제원집계 로직 수정 — 각 행의 "설비대수"를 곱하지 않던 실수를 바로잡음

- UTILITY 공통 항목인 **설비대수**(같은 유형의 설비가 몇 대인지)가 업로드 양식에는 있었지만, 지금까지
  제원집계 로직(`computeAggregation`/`itemAggValue`, 실제 백엔드의 `compute_aggregation`도 동일)이 이
  값을 곱하지 않고 있었습니다 — 설비가 여러 대여도 늘 1대인 것처럼 집계됐습니다. 이제 각 행의
  amount(필드 곱)에 그 행의 설비대수까지 곱합니다. 설비대수 열이 없거나 그 행에 값이 비어 있으면
  기존과 같이 1대로 취급해(하위 호환) 계산이 달라지지 않습니다. **데모·실제 백엔드 양쪽 다 고쳤습니다**
  (`backend/app/services/aggregation.py`도 함께 수정).
- "그래프 만들기"의 값(Values) 목록도 맞춰 고쳤습니다 — 지금까지는 필드가 2개인 대분류(GAS/AIR 등)만
  원본 필드에 더해 "집계값(__agg__)"을 추가로 제공했는데, 필드가 1개뿐인 대분류(POWER·UPW·CHEMICAL·
  폐액·SPECIALITY GAS)도 설비대수 배수가 있으면 원본 필드 값과 총량이 달라지므로, 이제 모든 대분류에
  동일하게 "필드×...×설비대수 집계값"을 맨 위 옵션으로 제공합니다(`pivotMeasureFieldsFor`). SUMMARY
  탭 카드의 measureKey도 항상 이 집계값을 쓰도록 함께 맞춰, 카드 합계·미니 그래프·"그래프 만들기"·AI
  챗봇이 항상 같은(설비대수 포함) 숫자를 가리킵니다.
- 업로드 파서(`parseGroupedWorkbook`)가 이제 설비대수를 실제로 각 항목에 붙입니다 — 예전에는 인식만
  하고 값을 버렸습니다. 같은 행에서 여러 대분류의 항목이 나오면(한 물리 설비가 GAS/AIR·POWER 속성을
  동시에 가지는 경우 등) 그 행의 설비대수를 모든 항목에 동일하게 붙입니다.
- **제원 DB** 탭과 제원표 상세의 항목 표시·엑셀 다운로드(`DB_EXPORT_HEADERS`)에 **설비대수** 열이
  새로 추가됐습니다 — 지금까지 업로드 양식에 있는 이 열이 화면 어디에도 보이지 않았습니다.
- 더미 데이터(998개 제원표)도 항목마다 설비대수를 채워 넣어(대부분 1대, 가끔 2~3대) 집계 결과에서
  실제로 곱셈 효과가 보이도록 했습니다. 데모 시트 PD000102의 GAS/AIR H2(2대)와 SPECIALITY GAS
  WF6(3대)로 손으로 검산해 확인했습니다.

### "수동질의 등록" 탭 — 대공정·건설코드·설비모듈에 "전체" 옵션 + 일괄(bulk) 질의

- 대공정·건설코드·설비모듈 세 필수 선택 모두에 **"전체"** 옵션이 추가됐습니다. 대공정=전체를 고르면
  그 밑 건설코드도 전체 목록(선택한 PJT 범위 안 모든 시트)에서, 설비모듈=전체를 고르면 그 조건에
  맞는 항목 전부가 대상 후보에 오릅니다(`manualQueryItemPool`) — 대공정을 예로 들면 건설코드 목록이
  너무 길어질 수 있어(500건 초과 시) 개별 선택 목록은 상위 500건까지만 보여주고 "전체 건설코드"는
  항상 전부를 대상으로 삼습니다.
- 대상 후보가 여러 건이면 "대상 항목" 선택지 맨 위에 **"전체 (N건 모두 — 일괄 적용)"** 이 추가됩니다.
  이걸 고르면 같은 필드·TO-BE를 후보 전체(최대 300건, `MQ_MAX_BULK_TARGETS`)에 동일하게 적용하는
  질의 1건을 만듭니다 — 기존 AUTO 질의 일괄 생성·"값 제안(대상 여러 건)" 화면과 같은 `targets` 배열
  구조를 그대로 재사용해서, 등록 후 "질의응답" 탭에서 대상 N건이 한 표(건설코드/설비모듈/필드/AS-IS/
  TO-BE)로 나란히 보입니다.
- 대상이 여러 대분류에 걸쳐 있으면(예: 설비모듈=전체로 GAS/AIR·POWER가 섞임) 모든 대상에 공통으로
  존재하는 필드만 고를 수 있게 좁힙니다(`manualQueryFieldIntersection`) — 대분류마다 있는 필드가
  다르므로, 없는 필드를 잘못 적용하는 일이 없도록 합니다. 공통 필드가 하나도 없으면 안내 문구와 함께
  등록을 막습니다.
- **대상이 여러 대공정에 걸쳐 있으면 제출 자체를 막습니다** — 수동 질의 1건은 담당 기술팀 하나가
  처리해야 하는데(majorProcess가 하나여야 역할 기반 접근 제어가 성립합니다), 대공정=전체로 넓게
  검색한 결과가 여러 대공정에 걸치면 어느 담당 기술팀에게 보낼지 정할 수 없기 때문입니다. 이 경우
  걸쳐 있는 대공정 목록을 보여주며 대공정을 특정하거나 조건을 좁히도록 안내합니다.
- 일괄 모드에서는 AS-IS(현재값)가 항목마다 달라 하나로 보여줄 수 없으므로 "(항목마다 다름 · N건)"으로
  표시하고, TO-BE만 입력받아 전체에 동일 적용합니다. 검증 규칙(성상별 유량 OVER 등)도 대상 전체에
  대해 각각 확인해 통과 못 한 항목이 있으면 등록을 막습니다.

### 제원 부분접수 지원 — "제원표 업로드" 자동 누적 + "제원 수기입력" 탭 신설 + 업무 가이드 흐름도 추가

처음부터 100% 풀패키지 제원표가 한 번에 들어오는 것이 아니라, 같은 건설코드로 여러 차례에 걸쳐
조금씩(부분접수) 들어올 수 있다는 전제를 반영했습니다.

- **"제원표 업로드" 탭 — 자동 누적(accumulate).** 이미 존재하는 건설코드를 다시 업로드하면 기존
  항목을 통째로 덮어쓰지 않고, 새로 들어온 항목만큼 누적합니다(`mergeItemsAccumulate`). 대분류·
  키값(성상명/전원종류/자재명)·설비모듈이 모두 같은 항목은 최신값으로 갱신(정정으로 간주)하고, 그
  외에는 새 항목으로 추가합니다(`specItemMatchKey`). 업로드 결과 박스에 신규/누적 건설코드 수와
  건설코드별 추가·갱신 건수를 함께 보여줍니다.
- **"제원 수기입력" 탭(신설, 기술팀 담당자 전용).** 협의된 엑셀 양식이 아닌 형태(메일·구두·비정형
  문서 등)로 제원이 들어왔을 때, 기술팀 담당자가 항목을 직접 추가·수정·삭제합니다. 항목 구성
  (대분류별 키 필드·값 필드)은 `CATEGORY_ITEM_SCHEMA`로 "제원표 업로드" 탭이 인식하는 협의된 양식과
  동일하게 맞춰 두어, 여기서 입력한 값도 별도 저장소 없이 `state.sheets`를 그대로 갱신하므로 제원 DB·
  제원집계·그래프 만들기·질의응답 등 다른 화면에 업로드 데이터와 완전히 동일하게 반영됩니다. 기존
  건설코드에 항목을 추가/수정/삭제할 수도 있고, 그 자리에서 새 건설코드를 만들 수도 있습니다. 기술팀
  담당자는 자신이 담당하는 대공정만, 관리자는 전체 대공정을 다룰 수 있습니다.
  - 새 건설코드용 입력 필드(건설코드/PJT/제목/위치)는 그 아래 "대분류" 선택이 페이지 전체를 다시
    그리기 전에 입력되므로, 상태(`state.specEntryForm`)에 매 입력마다(`oninput`) 동기화해 두어야
    대분류를 고르는 순간 값이 지워지지 않습니다 — 처음에는 `onchange`로만 저장했다가 사라지는 문제를
    Playwright로 재현해 고쳤습니다.
  - 버전 이력에는 새 출처 `MANUAL_ENTRY`("기술팀 수기입력")로 기록됩니다.
- **업무 가이드 탭 — 흐름도 추가.** "전체 처리 흐름"(SPEC 질의) 앞에 새 흐름도(`buildIntakeFlowSvg`)를
  추가해 제원 접수 단계 자체를 그렸습니다: 접수①(제원표 도착) → 협의된 양식 여부 분기 → 접수②(제원표
  업로드, 자동 누적) 또는 접수③(제원 수기입력) → 접수④(제원 DB 반영). 접수④에서 접수①로 돌아가는
  점선(주황) 루프로 "남은 제원이 나중에 도착하면 반복해서 누적됨(부분접수)"을 표현했습니다. 회색
  마름모는 사람이 아니라 접수 형태로 갈리는 시스템 분기임을 나타내려고 기술팀(청록)/설계사(주황)
  분기와 다른 색을 썼습니다. "단계별 설명" 목록에도 접수①~③ 항목을 맨 앞에 추가했습니다.
  - 처음에는 이 접수①~④ 라벨에 원문자 "Ⓘ"(CIRCLED LATIN CAPITAL LETTER I, U+24BE)를 썼는데, 이
    폰트 스택에서 "①"(원문자 숫자 1)과 구분되지 않게 렌더링되어("Ⓘ①"이 "①①"처럼 보임) 스크린샷으로
    확인 후 "접수①"처럼 한글 단어 접두어 방식으로 바꿨습니다(기존 SPEC 흐름의 "①-⑥", NON_SPEC
    흐름의 "Ⓝ①-Ⓝ③"과 헷갈리지 않도록 구분되는 접두어를 골랐습니다 — "Ⓝ"은 이 폰트에서 정상
    렌더링되는 것도 확인했습니다).

### "제원 수기입력" — 건설팀 담당자 승인 게이트 추가 (새 역할: 건설팀 담당자)

기술팀이 "제원 수기입력" 탭에서 추가·수정·삭제한 내용이 곧바로 제원 DB에 반영되던 것을, 담당 대공정의
**건설팀 담당자**가 승인해야만 실제로 반영되도록 바꿨습니다.

- **새 역할 `CONSTRUCTION_LEAD`("건설팀 담당자")**를 추가했습니다. 기술팀 담당자와 마찬가지로
  대공정별로 담당 범위가 지정되고, "사용자 관리" 탭에서 똑같은 방식(담당 대공정 체크박스)으로 등록·
  관리합니다. 데모 시드에 CVD·ETCH 담당 건설팀 담당자 2명을 추가했습니다.
- **승인 대기 큐(`spec_entry_requests`).** 기술팀이 항목을 추가/수정/삭제하면 곧장 `state.sheets`를
  바꾸는 대신, 이 새 컬렉션에 PENDING 요청으로만 쌓입니다(`specEntryRequestAdd/Update/Delete`).
  담당 대공정의 건설팀 담당자(또는 관리자)가 "제원 수기입력" 탭에서 그 요청을 보고 **승인**하면 그
  시점의 최신 제원표에 실제로 반영되고(`approveSpecEntryRequest` → 기존 `saveSheetVersion` 그대로
  호출), **반려**하면 DB는 전혀 바뀌지 않고 반려 사유만 기술팀에게 남습니다. **관리자만 예외**로 승인
  절차 없이 기존처럼 곧장 반영됩니다(최상위 역할이므로).
- 기술팀 화면에는 "내 요청 현황"(내가 제출한 요청의 대기/승인/반려 상태, 대기 중이면 취소 가능),
  이미 요청이 걸린 항목에는 "⏳ 변경/삭제 요청이 승인 대기 중" 배지와 함께 중복 요청을 막기 위해
  버튼이 비활성화됩니다. 건설팀 담당자 화면은 승인 대기 큐 + 최근 처리 이력만 보여주는 전용 화면이고,
  관리자 화면에는 전체 승인 대기 목록이 추가로 붙습니다.
- 새 건설코드를 만드는 요청도 첫 항목이 승인되기 전까지는 시트가 실제로 생성되지 않으므로, 승인 대기
  중인 신규 항목 목록을 화면에 별도로 보여줍니다.

### 업무 가이드 탭 — 제원 접수 흐름도에 "건설팀 담당자 승인" 단계 반영 + 화살표 겹침 수정

위 승인 게이트를 추가하면서 업무 가이드 탭의 제원 접수 흐름도(`buildIntakeFlowSvg`)가 실제 프로세스와
어긋나 있던 것을 바로잡았습니다(접수③ 제원 수기입력이 곧장 접수④로 이어지는 옛 그림 그대로였습니다).

- 접수③(제원 수기입력)과 접수④(제원 DB 반영) 사이에 새 분기 도형 **"접수③-A 건설팀 담당자 승인"**을
  추가했습니다. 승인(예)하면 접수④로 진행하고, 반려(아니오)하면 점선(주황) 화살표로 접수③으로
  되돌아가 기술팀이 다시 제출합니다. 접수②(제원표 업로드, 자동 파싱)는 승인 절차가 없으므로 지금처럼
  곧장 접수④로 이어집니다. "단계별 설명" 목록에도 접수③-A 항목을 추가했고, 가이드 편집 화면의 역할
  드롭다운에 **"건설팀"**을 새로 추가해 이 단계에 배정할 수 있게 했습니다(칩 색상도
  `role-CONSTRUCTION_LEAD`로 구분됩니다).
- 사용자가 스크린샷으로 지적해 발견한 **화살표 겹침 버그 2건**도 함께 고쳤습니다.
  1. 접수②·접수③ 두 경로가 접수④ 박스로 합류하는 지점의 진입 x좌표가 너무 가까워(300/460, 160px
     차이) 두 화살촉이 붙어 보였습니다 — 진입 x좌표를 280/480(200px 차이)으로 벌리고, 두 화살표 모두
     마지막 구간을 "수직으로 곧장 내려와 윗변에 닿는" 형태로 바꿔(원래 하나는 수평 구간이 윗변에
     닿는 형태였음) 화살촉이 항상 박스 완전히 바깥에 위치하도록 했습니다.
  2. 전체 질의응답 흐름도(`buildFlowSvg`)에서 설계사 반려 시 "④ 기술팀 처리" 박스로 돌아가는 재질의
     점선 화살표가, 박스의 **왼쪽 변(수직 변)에 수직 방향(위로 곧장)으로 진입**하고 있어 화살촉이
     옆으로 튀어나와 박스 경계에 걸쳐 보였습니다 — 진입 지점을 **아랫변(수평 경계)에 수직으로 곧장
     올라가 닿는 형태**로 바꿔(왼쪽 변 진입 대신 아랫변 진입) 화살촉이 박스 바깥(아래)에 완전히
     위치하도록 했습니다.
  - 두 경우 모두 "화살표의 마지막 구간이 진입 변과 나란한(평행) 방향이면 화살촉이 경계에 걸쳐
    겹쳐 보인다"는 같은 원인이었습니다 — 상단 "플로우차트 배치 지침" 주석에 이 규칙(6번 항목)을
    명시적으로 추가해 두었습니다.

### "MY TASK" 탭 — 지금 로그인한 사람이 당장 처리할 일만 모아 보기

상단 네비게이션에 **"MY TASK"** 탭을 추가했습니다. 역할별로 이미 있는 판단 기준(질의응답 탭의
`techActionCategory`/`designerActionCategory`, 제원 수기입력의 `specEntryRequestsForApprover`)을 그대로
재사용해, 새로운 판단 로직을 따로 만들지 않고 "지금 조치가 필요한 것"만 한 화면에 모읍니다.

- **기술팀 담당자**: 판단/답변이 필요한 질의(AUTO 확인 필요·서술형 답변 필요 등) 목록.
- **건설팀 담당자**: 담당 대공정의 제원 수기입력 승인 대기 목록(승인/반려 버튼 그대로 동작).
- **설계사**: 최종확인·최종검증이 필요한 질의만(기술팀 처리를 기다리기만 하는 질의는 "내가 할 일"이
  아니므로 제외).
- **관리자**: 위 세 가지를 전부 합쳐서 봅니다.
- 질의 카드를 클릭하면 필터를 모두 초기화하고 "질의응답" 탭의 해당 질의 상세로 바로 이동합니다(필터에
  가려 안 보이는 일이 없도록).

### 상단 탭에 커서를 올리면 설명이 뜨는 툴팁 추가

상단 네비게이션의 모든 탭 버튼에 `title` 속성을 채워, 커서를 올리면 그 탭이 무엇을 하는 화면인지 한
줄 설명이 뜹니다(`PAGES` 배열의 `desc` 필드). 잠긴(🔒) 탭에는 "사용자를 먼저 선택해 주세요" 또는
"현재 역할로는 접근할 수 없습니다"라는 이유도 함께 붙습니다.

### 업무 가이드 탭 플로우차트 — 겹침 방지 지침 강화

세 플로우차트(`buildFlowSvg`/`buildNonSpecFlowSvg`/`buildIntakeFlowSvg`) 모두 좌표 계산과 확대
스크린샷으로 화살표·도형·라벨이 서로 겹치지 않는지 다시 확인했고, 상단의 "플로우차트 배치 지침"
주석에 화살표-화살표 교차 금지를 명시적으로 추가하고, 화살촉이 잘려 보이는 z-order 문제(화살표의
마지막 구간이 진입 도형 가장자리와 평행할 때 도형을 화살표보다 먼저 그려야 하는 규칙)를 별도 항목으로
정리해 앞으로 도형을 옮기거나 새로 추가할 때 항상 지키도록 했습니다.

### 제원 접수 흐름도 — 업로드 주체 명시 + 부분접수 라벨 위치 버그 수정

사용자가 캡처 스크린샷으로 지적한 두 가지를 `buildIntakeFlowSvg`에서 고쳤습니다.

- **접수② 제원표 업로드 박스에 주체 명시**: 접수③ 박스가 "기술팀이 같은 양식으로 직접 추가/수정/삭제
  요청"이라고 주체를 명시하는 것과 달리, 접수② 박스에는 주체가 빠져 있었습니다(실제 업로드 화면은
  이미 관리자 계정으로만 열림 — `renderUploadPage`). 박스 문구에 **"관리자만 업로드 가능"** 줄을
  추가해 그림만 보고도 업로드 권한이 관리자 전용임을 알 수 있게 했고, 3줄이 된 만큼 박스 높이를
  다른 3줄 박스(접수③)와 같은 64→72로 맞추면서 위/아래로 드나드는 화살표의 진입·이탈 y좌표(344/416)
  도 함께 조정했습니다.
- **"부분접수 —" 라벨이 화살표에서 멀리 떨어져 허공에 떠 보이던 버그**: 접수④→접수①로 돌아가는
  점선 되돌이 화살표의 라벨(`inPartial`)이, 그 화살표의 실제 경로(우측 x=950 세로선 등) 어디와도
  닿지 않는 좌표(690,260)에 놓여 있어 화면에 문맥 없이 툭 떨어진 것처럼 보였습니다 — 라벨을 그
  화살표의 첫 구간(접수④ 오른쪽에서 시작하는 y=665 수평선) 바로 아래(740,715)로 옮겨 어떤 화살표를
  설명하는 라벨인지 한눈에 보이도록 했습니다.

### 업무 가이드 탭 — 부분접수 누적 기준 게시 + 업로드 탭 적용/미적용/삭제 관리(관리자 전용)

**부분접수 누적 기준**: "제원 접수 흐름" 플로우차트 바로 아래에 "부분접수 누적 기준 — 접수②(제원표
업로드)" 패널을 새로 추가해, 같은 건설코드를 다시 업로드했을 때의 실제 동작을 명문화했습니다 —
(1) 대분류+키값(성상명/전원종류/자재명)+설비모듈이 모두 같아야 "같은 항목"으로 판단하고, (2)
매칭되면 확인 절차 없이 곧바로 덮어써 갱신하며(이전 값은 "버전 이력"에 보존), (3) 매칭되지 않으면
새 항목으로 추가(누적)되고, (4) 이 과정은 질의(질의응답)로 자동 전환되지 않습니다(검증 규칙 위반
항목만 별도로 자동 질의가 생성됩니다).

**업로드된 제원표 관리(관리자 전용)**: "제원표 업로드" 탭 하단에 새 패널을 추가해, 엑셀로 업로드한
(현재 버전의 출처가 UPLOAD인) 제원표를 건설코드 단위로 관리할 수 있게 했습니다 — 잘못된 제원표를
올렸을 때 재접수를 받을 수 있어야 한다는 요구에 따른 기능입니다.

- 제원표마다 **적용/미적용 전환** 버튼과 **삭제** 버튼을 붙였습니다. "미적용"은 값을 지우지 않는
  소프트 삭제로, `sheet.applied` 플래그만 바꿉니다 — `sheetList()`를 쓰는 대시보드·제원 DB·SUMMARY·
  그래프 만들기·질의응답 대상·수동질의 등록·제원 수기입력의 건설코드 목록과 자동 질의 생성
  (`generateAutoQueries`)에서 즉시 제외되고, 다시 "적용으로 전환"하면 그대로 복원됩니다. 같은
  건설코드를 올바른 내용으로 재업로드하면 자동으로 다시 적용 상태가 됩니다.
- "삭제"는 `store.deleteSheet`(로컬/Artifact `db` 스토어 모두에 새로 추가)로 제원표 문서 자체를
  완전히 지우는, 되돌릴 수 없는 동작입니다 — 값을 보존한 채 화면에서만 빼려면 삭제 대신 미적용을
  먼저 권하도록 확인 대화상자에 안내했습니다.
- 이 관리 UI는 "제원표 업로드" 탭 안에만 두었고, 그 탭 자체가 이미 관리자 전용으로 게이팅되어 있어
  별도 권한 체크 없이도 관리자만 쓸 수 있습니다 — 코드에 "지침(항상 지킬 것)" 주석으로 이 규칙과,
  제원표 목록을 새로 가져오는 화면은 항상 `sheetList()`(또는 `sheetApplied()`)를 거쳐야 한다는
  원칙을 남겼습니다.
- 제원표 상세 화면에도 미적용 상태일 때 "미적용" 칩을 붙여, 목록에는 안 보여도 직접 링크로 들어오면
  상태를 알아볼 수 있게 했습니다.
